# IPE-L0126: non-Clone capture in a closure is not yet supported

A closure captured a binding whose type does not implement `Clone` — such as a
`Task`, `Fn`/function value, `Decoder`, `Cmd`, or `Sub` — and used it in a
position other than a direct function call.

The Rust backend lowers Ipe closures to `Box<dyn Fn(…) -> …>`, which requires
captured bindings to be cloneable (so the closure can be called multiple times).
Closures that *call* a captured function are fine today — `Fn::call` only
borrows the capture. But forwarding a function-typed value out of a closure
(storing it in a record, returning it, passing it to another HOF) consumes the
capture, making the closure `FnOnce` when a `Fn` slot is required.

## How to fix

**Call the function inside the closure** instead of forwarding the value:

```ipe ipe:error
-- before (forwarding — IPE-L0126)
let wrapped = \x -> applyTwice f x  -- f is a function; forwarded, not called

-- after (call at the use site)
let wrapped = \x -> f (f x)
```

**Bind the result outside the closure** when possible:

```ipe ipe:error
-- before
let result = someTask |> Task.andThen (\_ -> otherTask)

-- if otherTask can be evaluated once and reused, bind it first:
let theResult = Task.run otherTask
let result = someTask |> Task.andThen (\_ -> Task.succeed theResult)
```

**Wrap the forwarding in a named top-level function** when the closure must
pass the function along:

```ipe ipe:error
-- before (closure forwarding a decoder)
let mapped = \d -> JsonDec.map transform d

-- after (top-level named function)
mappedDecoder d =
    JsonDec.map transform d
```

## Shared handlers

A `Stream.stream` handler, a `Ui.on*` event handler and an `Ipe.Html.Events`
handler are shared and called again and again, and each value they capture is
copied into the handler. Every capture must therefore be copyable: a function
bound through a tuple or record destructure, a `Task`, `Cmd`, or `Sub`, or a
value whose type could not be determined is refused at the capture. A partially
applied or point-free handler kernel is a separate error, IPE-L0152.

```ipe ipe:error
-- before (destructure-bound function captured — IPE-L0126)
let ( f, g ) = ( \s -> s, \s -> s )
in Stream.stream "text/plain" (\w -> Stream.emit (f "x") w)

-- after (plain `let` binding, or a parameter)
let f = \s -> s
in Stream.stream "text/plain" (\w -> Stream.emit (f "x") w)
```

## Partial applications passed as functions

A partial application passed where a function is expected, such as
`Task.andThen (\x -> h x)` given to `List.map`, is rebuilt as a closure over its
supplied arguments. When an argument reads a `Task` or `Decoder` value, or a
function bound by a pattern (a tuple, record or `case` destructure), the rebuilt
closure moves that value on its first call and can run only once. It is refused
wherever the receiving position may call it again: a `List.map` mapper, a stored
or returned function, or an argument to a user function. The error points at the
moved value. The same partial application fed straight into `Task.andThen` runs
once and is accepted.

A handler given to a kernel that calls it again and again — a `Ui.on*` event
handler, an `Ipe.Ui.Input` callback field, `Lazy.lazy`'s view, or the task
`Task.retryWith` re-runs — is refused the same way when it is a partial
application over a `Task` or `Decoder` value: `Ui.onKeyDown (h t)` with `t` a
`Task` parameter is refused at `t`.

Take a captured function as its own parameter, or bind it with a plain `let`, so
it is shared. For a captured `Task` or `Decoder`, write an explicit lambda that
builds it inside its body instead of capturing the built value.

```ipe ipe:error
-- before (destructure-bound `h` moved into a rebuilt closure — IPE-L0126)
run ( h, _ ) ts =
    List.map (Task.andThen (\x -> h x)) ts

-- after (the function is its own parameter, so it is shared)
run h ts =
    List.map (Task.andThen (\x -> h x)) ts
```

A `let`-bound partial applied to an argument that cannot be copied, such as a
`Maybe (Int -> Bool)` parameter, is rebuilt the same way: `k m` below moves `m`
into a closure that `List.filter` calls once per element, so it is refused at
`m`. Apply the partial fully where it is used instead, so no closure holds `m`.

```ipe ipe:error
import Ipe.Io as Io
import Ipe.List as List
import Ipe.Maybe as Maybe
import Ipe.String as String


-- before (the partial `k` moves `m` into a closure called per element — IPE-L0126)
count : Maybe (Int -> Bool) -> List Int -> Int
count m xs =
    let
        k =
            Maybe.withDefault (\n -> n > 1)
    in
    List.length (List.filter (k m) xs)


main : Task Error ()
main =
    Io.println (String.fromInt (count Nothing [ 1, 2, 3 ]))
```

```ipe
import Ipe.Io as Io
import Ipe.List as List
import Ipe.Maybe as Maybe
import Ipe.String as String


-- after (the kernel is applied fully at its use, so `m` is read, not moved)
count : Maybe (Int -> Bool) -> List Int -> Int
count m xs =
    List.length (List.filter (Maybe.withDefault (\n -> n > 1) m) xs)


main : Task Error ()
main =
    Io.println (String.fromInt (count Nothing [ 1, 2, 3 ]))
```

## Why this happens

Ipe closures lower to `Box<dyn Fn(…) -> …>` in Rust. Captured values that are
not `Clone` can only be consumed once, producing `FnOnce`; but the `Fn` trait
is required for closures that may be called more than once. This restriction will
be relaxed in a future release once first-class function values gain a richer
representation.

## Types affected

- `Task a` / `Cmd a` / `Sub a`
- Function types (`a -> b`)
- `Decoder a`
- Server request / response / route types
