# IPE-L0144: argument at a row-generic position is not a record

A function whose parameter is annotated `any` and whose body reads record fields
is lowered to a **row-generic**: Ipê erases the `any` and emits a Rust generic
bounded by one `IpeHas*` witness trait per field read. Only a record type can
satisfy those bounds. Passing a non-record value — an `Int`, `Bool`, `String`,
a function, or a custom ADT — at that position produces Rust that fails to
compile with `error[E0277]`, even though the type-checker accepted the call
(because `any` intentionally severs the normal check that a caller's argument
type matches the callee's parameter type). This diagnostic catches the mismatch
at Ipê time.

```ipe ipe:skip the non-record-argument shape IPE-L0144 flags; shown without running the checker
getName : any -> String
getName p =
    p.name

-- wrong: 5 is an Int, not a record with a `name` field
result = getName 5
```

Only a record with the required fields is accepted at a row-generic parameter
position.

## How to fix

**Pass a record value.** The callee reads record fields, so the argument must be
a record that carries those fields:

```ipe ipe:skip the record-argument fix; shown without running the checker
getName : any -> String
getName p =
    p.name

result = getName { name = "Ada" }
```

**Or annotate the callee's parameter with a closed record type.** A closed record
type (`{ name : String }`) lets the type-checker reject a non-record argument
before lowering, with a clearer type-error message:

```ipe ipe:skip the closed-record-annotation fix; shown without running the checker
getName : { name : String } -> String
getName p =
    p.name

-- now a type error at check time, not a lowering rejection:
result = getName 5
```

**Or use a row-polymorphic annotation** if you want to accept any record that
carries at least the required fields:

```ipe ipe:skip the row-polymorphic-annotation fix; shown without running the checker
getName : { r | name : String } -> String
getName p =
    p.name
```

## Why this happens

A wildcard `any` severs the normal check that a caller's argument type matches
the callee's parameter type: the type-checker accepts a call `f 5` where
`f : any -> String` because `any` is a one-shot placeholder the caller fills, not
a type variable that propagates field constraints back to the call site.

When `f`'s body reads `p.name`, the backend lowers `p` to a Rust generic bounded
by `IpeHasName<Name = String>`. That bound says the argument must be a record
carrying a `name` field. An `Int` carries no such trait and cannot satisfy the
bound — `error[E0277]`. Ipê catches this at lowering time so you see a clear
message instead of a `cargo` build failure.

## Glossary

- **wildcard `any`** — a placeholder for one concrete type the compiler determines
  from the surrounding context. Unlike a named type variable, it is not left open
  for callers to instantiate.
- **row-generic** — a Rust generic bounded by one synthesised witness trait per
  required field, monomorphised by `rustc` per record shape.
- **field-witness trait** — a synthesised `IpeHas<Field><Name = T>` trait the
  backend generates; its associated type `Name` carries the required field type.
- **E0277** — a Rust error: a required trait bound is not satisfied.
