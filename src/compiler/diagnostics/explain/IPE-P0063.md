# IPE-P0063: invalid path literal

The widget-hook path passed to `CustomElement.fromFile` fails compile-time path
validation. The path is a string literal, so it is checked at build time
through the same seal `Path.fromString` applies at run time. The two rejection
cases are:

**NUL byte** — the string contains a `\0` character. A NUL byte terminates a
C string at the syscall boundary, so `"safe.js\0../../etc/passwd"` reaches the
kernel as `"safe.js"` on some code paths and as the full string on others —
a classic poisoned-NUL bypass.

**Traversal escape** — the string's lexically-cleaned form starts with `..` or
`../`, meaning a relative path that climbs above the project root it is
resolved against. For example `"../escape.js"` and `"js/../../secret.js"` both
escape.

## Rejected examples

A path that escapes via `..` is rejected with IPE-P0063:

```ipe ipe:error
module Main exposing (..)
import Ipe.Ffi.Js.CustomElement as CustomElement exposing (CustomElement)

editor : CustomElement Int String
editor = CustomElement.fromFile "../escape.js"
```

A relative path that resolves above the root after cleaning is also rejected:

```ipe ipe:error
module Main exposing (..)
import Ipe.Ffi.Js.CustomElement as CustomElement exposing (CustomElement)

editor : CustomElement Int String
editor = CustomElement.fromFile "js/../../secret.js"
```

A path with a NUL byte (`\0`) is rejected too:

```ipe ipe:error
module Main exposing (..)
import Ipe.Ffi.Js.CustomElement as CustomElement exposing (CustomElement)

editor : CustomElement Int String
editor = CustomElement.fromFile "js/safe\0bad.js"
```

## Fix

Name a hook file that stays inside the project root:

```ipe ipe:skip illustrates a path that stays inside the project root, imports omitted
editor : CustomElement Int String
editor = CustomElement.fromFile "js/editor.js"
```

A path known only at run time is not a widget hook; build it with
`Path.fromString` and handle the `Result`:

```ipe ipe:skip illustrates checking a run-time path with a typed Result, imports omitted
fromUserInput : String -> Result Error Path
fromUserInput s = Path.fromString s
```
