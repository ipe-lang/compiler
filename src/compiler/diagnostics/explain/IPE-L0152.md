# IPE-L0152: a handler-wrapping kernel must be applied to all its arguments

`Stream.stream contentType handler` answers a request with a streamed body. The
handler is rebuilt for every request, and each value it captures is copied into
the rebuilt handler. To do that, the compiler needs the handler expression
itself, right where `Stream.stream` is called.

This error means `Stream.stream` was used **without all its arguments** — bound
to a name, passed as a value, or given only its content type. The handler then
reaches `Stream.stream` later, as a plain function value the compiler cannot
look inside, so there is no way to copy its captures safely. `Stream.stream` is
therefore legal **only as a call with both arguments**.

```ipe ipe:skip
import Ipe.Http.Server.Stream as Stream

-- Reject: `Stream.stream` is bound to a name (point-free), so the handler is
-- supplied later, out of sight.
respond =
    let
        streamWith = Stream.stream
    in
    streamWith "text/plain" (\writer -> Stream.finish writer)
```

```ipe ipe:skip
import Ipe.Http.Server.Stream as Stream

-- Reject: only the content type is given (partial application); the handler
-- arrives through the alias.
respond =
    let
        streamText = Stream.stream "text/plain"
    in
    streamText (\writer -> Stream.finish writer)
```

The same holds for every kernel that takes a handler and calls it again and
again: `Ui.onKeyDown`, `Ui.onInput` and the other `Ui.on*` events, the
`Ipe.Html.Events` handlers, the `Ipe.Ui.Input` callback fields, `Lazy.lazy`,
`Task.retryOn` and `Task.retryWith`. Each is legal only with its handler given
at the call.

```ipe ipe:skip a two-binding sketch of the refused and accepted spellings; a runnable program needs a full Ui app
import Ipe.Ui as Ui

-- Reject: `Ui.onKeyDown` is passed point-free, so its handler arrives later.
handlers =
    List.map Ui.onKeyDown [ KeyDown ]

-- Accept: the handler is given at the call.
handler =
    Ui.onKeyDown KeyDown
```

## How to fix it

Give the kernel its handler in the same call — for `Stream.stream`, its content
type and its handler. Piping the handler in with `<|` or `|>` is the same call,
so it is accepted too:

```ipe ipe:skip
import Ipe.Http.Server.Stream as Stream

-- Accept: both arguments at the call.
respond =
    Stream.stream "text/plain" (\writer -> Stream.finish writer)

-- Accept: the handler piped in is still a call with both arguments.
respondPiped =
    Stream.stream "text/plain" <| \writer -> Stream.finish writer
```

## Why the compiler refuses this

Under Ipê's soundness principle, a program the compiler accepts must build and
never fail at runtime. The per-call copy of the handler's captures is sound
only when every capture is known to be copyable, and that can be checked only
where the handler is written. A point-free or partial handler kernel hides the
handler from that check, so the compiler refuses it here instead of producing
code that would not build. This is a separate fact from IPE-L0126, which refuses
a handler whose capture cannot be copied.
