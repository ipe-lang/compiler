# IPE-L0119: app entry cfg must be an inline record literal

You gave an app entry point (`Web.tea`, `Tui.tea`,
`Cli.tea`, or `WebView.app`) a cfg that is not an inline record
literal — a let-bound
variable, a function result, or a piped value. The Rust backend reads the
cfg's fields (`init`, `update`, `view`, `subscriptions`, …) directly from the
record you write at the call site, so it needs the literal there, not a name
that stands for it.

`[feature: let-bound-app-cfg]`

This trips the gate:

```ipe ipe:skip a fragment; init, update, view, and subscriptions are assumed from context
main =
    let cfg =
            { init = init
            , update = update
            , view = view
            , subscriptions = subscriptions
            }
    in
    Web.tea cfg
```

Write the record inline instead:

```ipe ipe:skip a fragment; init, update, view, and subscriptions are assumed from context
main =
    Web.tea
        { init = init
        , update = update
        , view = view
        , subscriptions = subscriptions
        }
```

The same applies to `Webview.app`'s nested `window` record and its `size`
tuple — both must be inline literals:

```ipe ipe:skip a fragment; init, update, view, subscriptions, and window are assumed from context
main =
    Webview.app
        { init = init
        , update = update
        , view = view
        , subscriptions = subscriptions
        , window = { title = "My App", size = ( 800, 600 ) }
        }
        |> Task.run
```

Non-literal cfg lowering is tracked and will land in a future milestone.
