# IPE-L0145: a Store.eq column argument is not a usable field accessor

`Store.eq` and `Store.eqBy` name their column with a **field accessor** — a bare
`.field` like `.age`. At lowering the compiler reads that accessor, checks the
field against the store's row type, derives the column name, and binds the value
as a query parameter. The column argument you wrote falls outside that shape, so
the query leaf cannot be built.

```ipe ipe:skip a fragment; `store` is assumed from context
Store.query store
    |> Store.where (Store.eq .age 18)
```

There are four ways this argument can be rejected.

## The column is not a bare accessor

The column must be written as `.field`, not a let-bound name, a multi-step
lambda, or any computed expression — the accessor is what names the column.

```ipe ipe:skip a fragment; `col` and `query` are assumed from context
-- wrong: `col` is a let-bound value, not a `.field` accessor
Store.where (Store.eq col 18) query
```

Write the accessor inline:

```ipe ipe:skip a fragment; `query` is assumed from context
Store.where (Store.eq .age 18) query
```

## The field does not exist on the row

The accessor named a field the store's row type does not declare. Name a field
the row actually has (the same field the codec or column list declares).

## The field type is not a scalar under plain `eq`

Plain `Store.eq` binds only scalar fields — `String`, `Int`, `Bool`, `Float`.
A field whose type is an enum or a newtype has no type-derivable wire form, so
`eq` cannot bind it. Use `Store.eqBy` with the field's codec, which projects the
value to a bound value through the codec:

```ipe ipe:skip a fragment; `rankCodec` and `query` are assumed from context
Store.where (Store.eqBy rankCodec .rank Gold) query
```

## The derived column name is not a valid SQL identifier

The column name derived from the accessor must be a valid SQL identifier —
letters, digits, and underscore only. A field whose name falls outside that
charset is rejected here rather than reaching SQL.

## Why this happens

The typed query surface cannot express SQL injection: a column reaches SQL only
after the identifier gate accepts it, and every value binds as a parameter, never
interpolated into the query text. Reading the column from a `.field` accessor is
what makes the column a checked, closed identifier rather than a caller-supplied
string — so the compiler requires exactly that shape and fails closed on
anything else.

## Glossary

- **field accessor** — the bare `.field` form (e.g. `.age`), a one-argument
  function that reads a record field. The typed query leaf uses it to name a
  column.
- **scalar field** — a field whose type is `String`, `Int`, `Bool`, or `Float`;
  its bound value form is derivable from the type alone.
- **codec** — a value describing how a type is written to and read from storage;
  `Store.eqBy` uses it to project an enum or newtype value to a bound value.
- **bound parameter** — a value sent to the database as a `?` placeholder bind,
  never spliced into the query text — the mechanism that makes injection
  unrepresentable.
