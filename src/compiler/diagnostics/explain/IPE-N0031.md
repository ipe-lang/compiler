# IPE-N0031: type applied to the wrong number of arguments

The built-in container types have a fixed shape. `List`, `Maybe`, and `Set` each take exactly one type argument; `Dict` and `Result` each take exactly two. Give one too few or one too many and the type has no meaning — there is nothing to put in the missing hole, and nowhere for the extra argument to go. I point at the annotation that misapplies the constructor.

A one-argument container needs its element type:

```ipe
first : List Int -> Maybe Int
first xs =
    case xs of
        [] -> Nothing
        x :: _ -> Just x
```

The most common way to trip this is forgetting the parentheses around a nested container. Ipê reads type application left to right, so `Maybe List String` is `Maybe` applied to **two** arguments (`List` and `String`) — and `List` on its own, with no element type. Wrap the inner container so it is one argument:

```ipe
-- error: `Maybe` takes exactly 1 type argument, but 2 were given
labels : Maybe List String

-- fixed: the inner `List String` is parenthesised into a single argument
labels : Maybe (List String)
```

`Dict` and `Result` take two arguments — a bare `Dict`, or a `Dict String` with the value type missing, is rejected the same way. Supply both:

```ipe
-- error: `Dict` takes exactly 2 type arguments, but 1 was given
counts : Dict String

-- fixed: key and value
counts : Dict String Int
```

A union you declare follows the same rule: it takes exactly the type parameters its declaration lists, in a signature, an annotation, or another union's field. `type Box a` has one parameter, so `Box Int Int` names no type:

```ipe ipe:error
type Box a
    = Box a


unbox : Box Int Int -> Int
unbox b =
    case b of
        Box n ->
            n
```

A bare `Box` is refused the same way, even inside `Box`'s own declaration. Give it one argument per parameter:

```ipe
type Box a
    = Box a


unbox : Box Int -> Int
unbox b =
    case b of
        Box n ->
            n
```
