# IPE-L0155: a collection mapper needs more adapter parameters than one call site allows

A mapping kernel such as `List.map2` or `List.map5` can store functions in its
input collections. When the mapper you pass is a named function, the compiler
wraps it in an adapter. The adapter takes one parameter per mapper argument,
plus one for the mapper itself, plus one per argument of each stored function
it re-carries. One call site allows at most 16 of these parameters, so a larger
adapter is refused here, before any code is generated. A partial application
such as `List.map2 applyTo fs` also counts, at the same site, one parameter for
each argument it leaves for later.

```ipe ipe:skip the adapter-parameter-cap shape IPE-L0155 flags; shown without running the checker
wide : Int -> Int -> Int -> Int -> Int -> Int -> Int -> Int -> Int -> Int -> Int -> Int -> Int -> Int -> Int
wide a b c d e f g h i j k l m n =
    a

applyTo : (Int -> Int -> Int -> Int -> Int -> Int -> Int -> Int -> Int -> Int -> Int -> Int -> Int -> Int -> Int) -> Int -> Int
applyTo fn x =
    x

-- Reject: 1 (mapper) + 2 (mapper arguments) + 14 (arguments of `wide`) = 17.
results =
    List.map2 applyTo [ wide ] [ 1 ]
```

```ipe ipe:skip a fragment; applyAll and f are assumed from context
-- Reject: five stored functions of three arguments each need
-- 1 + 5 + 15 = 21 adapter parameters.
totals =
    List.map5 applyAll [ f ] [ f ] [ f ] [ f ] [ f ]
```

## How to fix it

Pass the mapper as a lambda. A lambda needs no adapter for a stored function
it calls directly; only one it passes on as a value draws parameters:

```ipe ipe:skip a fragment; f is assumed from context
-- Accept: the lambda calls each stored function directly.
totals =
    List.map5 (\p q r s t -> p 1 2 3 + q 1 2 3 + r 1 2 3 + s 1 2 3 + t 1 2 3) [ f ] [ f ] [ f ] [ f ] [ f ]
```

You can also store functions that take fewer arguments, for example one record
or tuple in place of many separate arguments.
