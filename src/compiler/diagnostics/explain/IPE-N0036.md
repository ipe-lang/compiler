# IPE-N0036: a removed standard-library surface is still being called

You called a name like `Task.run` or `Task.perform`, and those names really did once live in the standard library — but they have been removed from the surface. I intercept the call here, before looking the member up, so you get a migration hint instead of a bare "no such member".

The names that are gone all shared one idea: they *forced* a `Task` to run synchronously, or fired one off outside the managed update loop. Ipê does not force effects by hand. A `Task` is a description of work; it runs only when the runtime performs it, either as your entry `main` or as a `Cmd` your `update` returns. That keeps every effect explicit and ordered, with no hidden blocking.

## `Task.run`

There is no synchronous "run this now". A `Task`-typed `main` is performed for you at the entry boundary, and mid-flow work is threaded with `Task.andThen`. So this:

```ipe ipe:error
import Ipe.Task as Task


type alias Config =
    {}


readConfig : Task Error Config
readConfig =
    Task.succeed {}


main : Task Error ()
main =
    Task.run readConfig
```

becomes a plain `Task` value that the boundary runs, with follow-up steps chained by `andThen`:

```ipe
import Ipe.Task as Task


type alias Config =
    {}


readConfig : Task Error Config
readConfig =
    Task.succeed {}


applyConfig : Config -> Task Error ()
applyConfig _config =
    Task.succeed ()


startServer : () -> Task Error ()
startServer _unit =
    Task.succeed ()


main : Task Error ()
main =
    readConfig
        |> Task.andThen applyConfig
        |> Task.andThen startServer
```

## `Task.perform` and `Task.attempt`

To turn a `Task` into a message your `update` receives, use `Task.attempt`, which reports both success and failure through a `Result`:

```ipe
import Ipe.Task as Task


type alias Config =
    {}


readConfig : Task Error Config
readConfig =
    Task.succeed {}


type Msg
    = GotConfig (Result Error Config)


loadConfig : Cmd Msg
loadConfig =
    Task.attempt GotConfig readConfig
```

Return that `Cmd` from `init` or `update`, and the runtime performs the `Task` and delivers `GotConfig` back into your loop. No synchronous force is needed, and errors stay in the type.
