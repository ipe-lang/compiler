# IPE-N0051: an app entry is built with a Model or Msg that is still a type variable

An app entry — `Web.tea`, `Web.embed`, `Web.appWith`, `Tui.tea`, `Cli.tea`,
`Worker.tea` — starts a running program. That program keeps its model between
events, serialises it for live reload and the debugger, compares models to skip
needless redraws, and prints messages in its logs. All of that needs to know the
exact `Model` and `Msg` types.

This error means the entry is built inside a definition that is generic over a
type variable (`msg`, `model`, `a`, …) which its cfg still mentions — typically
a helper that takes `update` or `view` as a parameter and wraps it in the app
cfg. A type variable there is a promise that the app works for *any* message
type, but a running app has exactly one.

## Example

```ipe ipe:error
module Main exposing (main)

import Ipe.Server.Http as Server
import Ipe.String as String
import Ipe.Task as Task exposing (Task)
import Ipe.Tea.Web as Web
import Ipe.Tea.Web.Cmd as Cmd
import Ipe.Tea.Web.Sub as Sub
import Ipe.Ui as Ui


type alias Model =
    { count : Int }


type Msg
    = Increment
    | NoOp


-- Rejected (IPE-N0051): `msg` is still open where the app is built.
embedOf : (msg -> Model -> ( Model, Cmd.Cmd msg )) -> (Model -> Element msg) -> msg -> Web.WebApp
embedOf step render fallback =
    Web.embed
        { init = \_ -> ( { count = 0 }, Cmd.none )
        , update = step
        , view = render
        , subscriptions = \_ -> Sub.none
        , routes = []
        , notFound = fallback
        }


update : Msg -> Model -> ( Model, Cmd.Cmd Msg )
update msg model =
    case msg of
        Increment ->
            ( { model | count = model.count + 1 }, Cmd.none )

        NoOp ->
            ( model, Cmd.none )


view : Model -> Element Msg
view model =
    Ui.text (String.fromInt model.count)


main : Task Error ()
main =
    Server.listen 8000 [ Server.mountApp "/" (embedOf update view NoOp) ]
```

## Fix

Give the helper the concrete types in its annotation instead of a type
variable:

```ipe

import Ipe.Server.Http as Server
import Ipe.String as String
import Ipe.Task as Task exposing (Task)
import Ipe.Tea.Web as Web
import Ipe.Tea.Web.Cmd as Cmd
import Ipe.Tea.Web.Sub as Sub

    { count : Int }


type Msg
    = Increment
    | NoOp
```

Or build the app directly where the model and message types are known:

```ipe
module Main exposing (main)

import Ipe.Server.Http as Server
import Ipe.Task as Task exposing (Task)
import Ipe.Tea.Web as Web
import Ipe.Tea.Web.Cmd as Cmd
import Ipe.Tea.Web.Sub as Sub
import Ipe.Ui as Ui


type alias Model =
    { count : Int }


type Msg
    = Increment
    | NoOp


init : WebReq -> ( Model, Cmd.Cmd Msg )
init _req =
    ( { count = 0 }, Cmd.none )


update : Msg -> Model -> ( Model, Cmd.Cmd Msg )
update msg model =
    case msg of
        Increment ->
            ( { model | count = model.count + 1 }, Cmd.none )

        NoOp ->
            ( model, Cmd.none )


view : Model -> Element Msg
view _model =
    Ui.text "hello"


subscriptions : Model -> Sub.Sub Msg
subscriptions _model =
    Sub.none


counterApp : Web.WebApp
counterApp =
    Web.embed
        { init = init
        , update = update
        , view = view
        , subscriptions = subscriptions
        , routes = []
        , notFound = NoOp
        }


main : Task Error ()
main =
    Server.listen 8000 [ Server.mountApp "/" counterApp ]
```

Helpers that return views (`Element msg`), commands, or subscriptions can stay
generic over `msg` — only the entry itself needs the concrete types.

## When nothing fixes the message type

The same error fires when no definition is generic but the program never says
what the message type is: an `update` that ignores its message
(`\_ model -> ( model, Cmd.none )`) and a view that emits none leave `msg` open.
(`notFound` names the route fallback, so it does not fix `msg`.)

```ipe ipe:error
module Main exposing (main)

import Ipe.Server.Http as Server
import Ipe.String as String
import Ipe.Task as Task exposing (Task)
import Ipe.Tea.Web as Web
import Ipe.Tea.Web.Cmd as Cmd
import Ipe.Tea.Web.Sub as Sub
import Ipe.Ui as Ui


type alias Model =
    { count : Int }


-- Rejected (IPE-N0051): nothing fixes `msg`.
counterApp : Web.WebApp
counterApp =
    Web.embed
        { init = \_ -> ( { count = 0 }, Cmd.none )
        , update = \_ model -> ( model, Cmd.none )
        , view = \model -> Ui.text (String.fromInt model.count)
        , subscriptions = \_ -> Sub.none
        , routes = []
        , notFound = ()
        }


main : Task Error ()
main =
    Server.listen 8000 [ Server.mountApp "/" counterApp ]
```

Fix it by using the message type where the app sees it — annotate `update`
(`update : Msg -> Model -> ( Model, Cmd Msg )`) or match on its message.

## Background

The app's runtime stores and serialises the model, compares it, and prints both
the model and the messages, so it requires the concrete types to support those
operations. Those requirements travel only through the cfg record, which is why
Ipê checks the entry itself: an entry whose `Model` or `Msg` is still open is
refused here, rather than accepted and then failing when the generated Rust
project is built.

Related: **IPE-N0046** (a `Web.tea` `init` annotated with a type variable for
its request argument), **IPE-L0119** (the cfg must be written inline at the
entry).
