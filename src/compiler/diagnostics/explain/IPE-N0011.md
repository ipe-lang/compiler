# IPE-N0011: constructor defined more than once

Two constructors share the same name. They may be in the same union or in different ones — either way, a constructor name has to be unique, because when you write the name in a pattern or an expression I have to know exactly which one you mean. I point at both definitions so you can see the clash.

To fix this, rename one of the constructors so each tag is distinct.

Here `Active` is used as a constructor in two different unions:

```ipe ipe:error
type Account
    = Active
    | Closed

type Session
    = Active
    | Expired
```

Give the colliding constructors distinct names:

```ipe
type Account
    = AccountActive
    | AccountClosed

type Session
    = SessionActive
    | SessionExpired
```

The same rule applies within a single union — every tag must appear only once:

```ipe
type Status
    = Pending
    | Done
    | Failed
```

The same code fires when a local constructor's name collides with one brought in by an EXPLICIT import (`exposing (Name(..))`) — that clash is refused right here, at the declaration, exactly like two local duplicates. A name shared only with an OPEN import (`exposing (..)`) is different: it defers to the first bare use instead (see IPE-N0024).
