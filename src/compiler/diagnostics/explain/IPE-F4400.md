# IPE-F4400: a foreign-call description cannot be rendered as valid Rust

While preparing a binding to a Rust crate, I found a foreign-call
description (the recipe that says *how* to invoke one function of that
crate) that is not structurally sound, so I refused it before writing
any code. This is deliberate: the alternative would be generating Rust
that fails to compile later, far away from the real cause.

## What a foreign-call description is

When you run `ipe add <crate>`, an inspector examines the crate and
records, for every function it can bind, a small structured recipe: the
call path, which argument feeds which slot, the receiver (for methods),
and the involved types. The binding generator replays that recipe to
write the Rust glue. Your Ipê code then calls the binding like any
other function:

```ipe ipe:skip illustrates calling a Rust crate binding, not a runnable program here
import Rust.Semver as Semver

main =
    println (Semver.parse "1.2.3")
```

## Why I stop here instead of later

Every structural rule this check enforces — argument indices that are
unique, contiguous, and in range; a receiver present exactly when the
call is a method; a closure only in a direct argument position; one
declared type per argument — is something the generated Rust needs to
even compile. A recipe that breaks one of them cannot be rendered
correctly, so the only sound moment to reject it is now, with a clear
message, rather than during the Rust build of your project.

For example, a recipe whose arguments skip an index could never supply
a value for the missing parameter:

```ipe ipe:skip illustrates the conceptual shape of a skipped-index recipe, not Ipe source
-- conceptually: a call using arg0 and arg2 but never arg1
-- there is no value to put in the middle slot, so the call
-- can never be rendered as `f(arg0, arg1, arg2)`
```

## What to do

This almost always means the cached binding data is stale or was edited
by hand. Regenerate it:

```ipe ipe:skip illustrates the shell commands to regenerate the binding, not Ipe source
-- from your project directory:
--   ipe remove <crate>
--   ipe add <crate>
-- a fresh inspection rewrites the cached recipe from scratch
```

If a freshly generated binding still reports IPE-F4400, the inspector
produced a recipe the generator cannot honour — that is a bug in the
toolchain, not in your code. Please report it, including the crate name
and version.
