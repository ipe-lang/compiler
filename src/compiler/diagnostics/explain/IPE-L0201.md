# IPE-L0201: a type nests too deeply for the backend

While writing the Rust code for your program, I met a type nested more deeply
than the backend is willing to emit. I stopped on purpose: the Rust compiler
refuses a type that nests past its own recursion limit, so emitting it would
only move the failure into the Rust build.

The type checker already refuses a type past its ceiling (IPE-T0022), so this
error is a second, independent check behind that one. Seeing it means a type
slipped past the first check, which is a gap in the compiler. Please report it
with the program that triggers it.

The shape that reaches it is a chain of definitions, each wrapping the one
before it:

```ipe ipe:skip an outline of a long chain; the real one is dozens of definitions
x0 = 0
x1 = Just x0
x2 = Just x1
-- … and so on, each wrapping the last …
```

## Right

Give the shape a name, so a value holds a known type instead of a growing one:

```ipe
type alias Pair =
    { left : Int, right : Int }

pair : Pair
pair =
    { left = 1, right = 2 }
```

When the data is a long sequence, keep it in a list, which is one level over
its element type however long it grows:

```ipe
values : List (Maybe Int)
values =
    [ Just 1, Nothing, Just 3 ]
```
