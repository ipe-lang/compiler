# IPE-F4411: a git source for a foreign crate was rejected

You asked me to bind a crate from a git repository, and the source you
gave did not pass the gate I put in front of anything that reaches the
network or a command line. I refused before contacting anything.

A successful git-sourced binding ends with an ordinary import:

```ipe ipe:skip illustrates calling a Rust crate binding, not a runnable program here
import Rust.Mylib as Mylib

greeting = Mylib.hello "world"
```

The gate below is what stands between the URL you typed and that
import existing.

## What the gate checks

A git source is accepted only when *all* of these hold:

1. **The scheme is `https://`.** I reject `http://` (no transport
   integrity), `file://` (a local-file read masquerading as a fetch),
   and everything else.
2. **The host is plainly spelled.** Letters, digits, dots, hyphens,
   underscores — nothing that could smuggle a second meaning into a
   URL or an argument list.
3. **The host is on the allowlist.** By default: `github.com`,
   `gitlab.com`, `codeberg.org`. Set `IPE_FFI_GIT_HOSTS` (comma-
   separated) to extend or replace it.
4. **At most one pin.** `rev`, `branch`, and `tag` are mutually
   exclusive — git itself cannot honour two at once, so asking for two
   is always a mistake I'd rather surface than guess about.

The crate *name* passes a gate of its own (letters, digits, `_`, `-`),
so a name can never carry shell metacharacters into a command.

## Why so strict

`ipe add` hands the URL to `cargo`'s git machinery and later compiles
what it fetched — code that then runs on your machine (see
`ipe doc IPE-F4410` for why compiling is running). A URL is
therefore an *input to a trust decision*, and I validate it into a
typed value before it can reach any command. There is no shell in this
path at all: arguments are passed as an argv list, so quoting tricks
have nothing to attack.

## What to do

- Use the crate's `https://` clone URL from a host on the allowlist.
- Pin with exactly one of `--rev`, `--branch`, or `--tag`.
- For another host you trust, set
  `IPE_FFI_GIT_HOSTS=example.com,github.com` and re-run.

Two shapes side by side:

```ipe ipe:skip illustrates a rejected command line, not Ipe source
-- rejected: http scheme, and two pins at once
--   ipe add mylib --git http://example.com/mylib --rev abc123 --tag v1
```

```ipe ipe:skip illustrates an accepted command line, not Ipe source
-- accepted: https, allowlisted host, exactly one pin
--   ipe add mylib --git https://github.com/acme/mylib --tag v1.2.0
```

## Glossary

- **allowlist** — a list of the only values accepted; everything not
  on it is refused. The fail-closed cousin of a blocklist.
- **pin** — fixing a dependency to one exact revision so today's build
  and next year's build fetch the same bytes.
- **argv** — the array of arguments a program receives directly,
  with no shell in between to reinterpret them.
