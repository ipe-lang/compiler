# IPE-L0122: `Web.route` `:param` count does not match page-constructor payload count

A `Web.route` call pairs a URL pattern (e.g. `"/apps/:id/:slug"`) with a page
constructor (e.g. `AppPage`). The number of `:param` segments in the pattern
must equal the number of payload fields the constructor declares — each segment
is delivered as an argument in order.

A mismatch means the route can never be correctly applied: too few segments
leave the constructor partially unapplied; too many fill extra payload slots
with the wrong values.

The simplest fix is to make the counts agree:

```ipe ipe:error
module Main exposing (main)

import Ipe.Tea.Web as Web
import Ipe.Tea.Web.Cmd as Cmd
import Ipe.Tea.Web.Sub as Sub
import Ipe.Ui as Ui

type Page = AppPage String   -- one payload field

type alias Model = { page : Page }

type Msg = NoOp

init : WebReq -> ( Model, Cmd.Cmd Msg )
init _req =
    ( { page = AppPage "x" }, Cmd.none )

update : Msg -> Model -> ( Model, Cmd.Cmd Msg )
update _msg model =
    ( model, Cmd.none )

subscriptions : Model -> Sub.Sub Msg
subscriptions _model =
    Sub.none

view : Model -> Element Msg
view _model =
    Ui.text "x"

main =
    Web.tea
        { init = init
        , update = update
        , view = view
        , subscriptions = subscriptions
        , routes = [ Web.route "/apps/:id/:slug" AppPage ]   -- ✘ two segments, one payload field
        , notFound = AppPage "none"
        }
```

```ipe ipe:skip the fix; give AppPage a second field, or drop the extra :slug segment
-- ✔ One segment, one payload field.
routes = [ Web.route "/apps/:id" AppPage ]

-- ✔ Two segments, two payload fields.
type Page = AppPage String String
routes = [ Web.route "/apps/:id/:slug" AppPage ]
```

For routes with no parameters use a nullary constructor and omit `:param`
segments entirely:

```ipe
module Main exposing (main)

import Ipe.Tea.Web as Web
import Ipe.Tea.Web.Cmd as Cmd
import Ipe.Tea.Web.Sub as Sub
import Ipe.Ui as Ui

type Page = DashboardPage

type alias Model = { page : Page }

type Msg = NoOp

init : WebReq -> ( Model, Cmd.Cmd Msg )
init _req =
    ( { page = DashboardPage }, Cmd.none )

update : Msg -> Model -> ( Model, Cmd.Cmd Msg )
update _msg model =
    ( model, Cmd.none )

subscriptions : Model -> Sub.Sub Msg
subscriptions _model =
    Sub.none

view : Model -> Element Msg
view _model =
    Ui.text "dashboard"

main =
    Web.tea
        { init = init
        , update = update
        , view = view
        , subscriptions = subscriptions
        , routes = [ Web.route "/dashboard" DashboardPage ]
        , notFound = DashboardPage
        }
```

Each `:param` segment fills exactly one payload field, in order — there is no
way to capture a variable number of segments into one `List` field (see
IPE-L0123 for which field types a segment can fill at all). Too many segments
mismatches the same way whether the extra payload would have been a `String`
field or something else:

```ipe ipe:error
module Main exposing (main)

import Ipe.Tea.Web as Web
import Ipe.Tea.Web.Cmd as Cmd
import Ipe.Tea.Web.Sub as Sub
import Ipe.Ui as Ui

type Page = ArticlePage String String   -- two payload fields

type alias Model = { page : Page }

type Msg = NoOp

init : WebReq -> ( Model, Cmd.Cmd Msg )
init _req =
    ( { page = ArticlePage "2024" "intro" }, Cmd.none )

update : Msg -> Model -> ( Model, Cmd.Cmd Msg )
update _msg model =
    ( model, Cmd.none )

subscriptions : Model -> Sub.Sub Msg
subscriptions _model =
    Sub.none

view : Model -> Element Msg
view _model =
    Ui.text "article"

main =
    Web.tea
        { init = init
        , update = update
        , view = view
        , subscriptions = subscriptions
        , routes = [ Web.route "/blog/:year/:month/:slug" ArticlePage ]   -- ✘ three segments, two payload fields
        , notFound = ArticlePage "" ""
        }
```
