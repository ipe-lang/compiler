# IPE-N0050: a Script imports a shape's UI, which it cannot render

This is a **hint**, not an error — your program still compiles and runs. Ipê is pointing out that you imported a **view** library into a **Script**, and a Script has nowhere to show a view.

## The short version

A **Script** is a program whose `main` is a plain `Task` — it runs some effects and exits. It has no `view`, so it draws nothing on a screen. If you `import Ipe.Ui`, `import Ipe.Html`, or `import Ipe.Ui.Cells` (the libraries you use to *build* a view) in a Script and never render the view, that view is a value you built and dropped. You probably meant to write an **app** — or, for a web view, to render it to a `String` (see the static-site exception below).

## Why this happens

In Ipê, **you write your shape — you never declare it.** The head of your `main` decides what kind of program you have:

- `main = Web.tea { … }` → a **web app** (renders a `Ui` / `Html` view in the browser).
- `main = Tui.tea { … }` → a **terminal app** (renders an `Ipe.Ui.Cells` view as terminal cells).
- `main = Cli.tea { … }` → a **command-line app** (renders lines).
- `main : Task Error ()` (a plain `Task`) → a **Script** (renders nothing).

An app carries a `view` field; the runtime calls it and paints the result. A Script has no such field — there is no `view` to call. So a `Ui` tree built in a Script is just an unused value.

This Script builds a view it can never show:

```ipe
module Main exposing (main)

import Ipe.Io as Io
import Ipe.Ui as Ui

-- a plain Task: this is a Script, so it renders nothing
main : Task Error ()
main =
    Io.println "hello"
```

## The exception: static-site generation

Building a `Ui` / `Html` view and **rendering it to a `String`** is a legitimate Script — static-site generation. The view *is* consumed: you turn it into HTML text and print or write it. Ipê recognises this and does **not** hint here. The carve-out is precise — the view counts as consumed only when your program references `Ipe.Html`'s render-to-`String` sink (`render`, `toString`, `htmlRender`, or `renderStatic`), resolved through your imports. A like-named `render` from some other module does not count, so a genuinely-dropped view still gets the hint.

```ipe
module Main exposing (main)

import Ipe.Io as Io
import Ipe.Ui as Ui
import Ipe.Html as Html

main : Task Error ()
main =
    Io.println (Html.render (Ui.layout [] (Ui.text "hello")))   -- the view is rendered to a String
```

`Ipe.Ui.Cells` (the terminal-cells view) has no render-to-`String` sink — only a `Tui.tea` app can render a `Screen` — so a Script that imports it always gets the hint.

## The fix

If you meant to **show that UI**, give `main` an app entry so it has a `view`:

```ipe
module Main exposing (main)

import Ipe.Tea.Web as Web
import Ipe.Ui as Ui
import Ipe.Tea.Web.Cmd
import Ipe.Tea.Web.Sub


type Page
    = HomePage


type Msg
    = NoOp


type alias Model =
    { page : Page }


init : WebReq -> ( Model, Cmd Msg )
init _req =
    ( { page = HomePage }, Cmd.none )


update : Msg -> Model -> ( Model, Cmd Msg )
update _msg model =
    ( model, Cmd.none )


view : Model -> Element Msg
view _model =
    Ui.text "hello"


subscriptions : Model -> Sub Msg
subscriptions _model =
    Sub.none


main =
    Web.tea
        { init = init
        , update = update
        , view = view          -- the runtime renders this
        , subscriptions = subscriptions
        , routes = [ Web.route "/" HomePage ]
        , notFound = HomePage
        }
```

If you really meant a **Script** — an effect that runs and exits — drop the view import; a Script has no use for it:

```ipe
module Main exposing (main)

import Ipe.Io as Io

main : Task Error ()
main =
    Io.println "hello"
```

## Glossary

- **Script** — a runnable module whose `main` is a plain `Task Error ()`. It performs effects and exits; it has no managed state and no `view`.
- **shape** — what a program *renders*: web, terminal, command-line, a server, or nothing (a Script). The shape is pinned by the head of `main`, never by a config field.
- **view** — the function an app hands to the runtime to draw a screen. Only apps (`Web.tea`, `Tui.tea`, `Cli.tea`) have one; a Script does not.

## See also

- **IPE-N0033** — the stricter, *error*-level cousin: a Script that imports the managed-update-loop machinery under `Ipe.Tea.*` is a contradiction and is rejected. This page (IPE-N0050) is only a hint, because importing a plain *view* library into a Script is legal — just probably not what you wanted.
