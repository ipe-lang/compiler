# IPE-E0004: no package.ipe in the project directory

ipe works on one project at a time, and a project is the directory that holds
its `package.ipe` manifest. The directory ipe was pointed at — the current
directory, or the directory you named on the command line — has none.

ipe never searches the directories above for a manifest. A `package.ipe` one
level up is a different project, and silently borrowing its settings (its
capabilities, its dependencies, its build options) would build your code under
rules you did not choose.

What to try:

1. **Run `ipe init` in the directory**, which writes a `package.ipe` and a
   `src/Main.ipe` to start from.
2. **Change into the project directory** — the one that holds `package.ipe` —
   and run ipe from there, or pass that directory as the argument.
3. If the directory holds a legacy `ipe.toml`, ipe says so instead: move its
   settings into a `package.ipe`.

Nothing in your source has to change. Once `package.ipe` exists, this
`src/Main.ipe` builds:

```ipe
module Main exposing (main)

import Ipe.Io as Io

main : Task ()
main =
    Io.println "hello"
```

A program with a top-level value builds the same way:

```ipe
module Main exposing (main)

import Ipe.Io as Io

greeting : String
greeting = "hello"

main : Task ()
main =
    Io.println greeting
```

So does one that imports more of the standard library:

```ipe
module Main exposing (main)

import Ipe.Io as Io
import Ipe.String as String

count : Int
count = 41 + 1

main : Task ()
main =
    Io.println (String.fromInt count)
```
