# IPE-E0004: no package.ipe in the project directory

ipe works on one project at a time, and a project is the directory that holds
its `package.ipe` manifest. The directory ipe was pointed at — the current
directory, or the directory you named on the command line — has none.

ipe never searches the directories above for a manifest. A `package.ipe` one
level up is a different project, and silently borrowing its settings (its
capabilities, its dependencies, its build options) would build your code under
rules you did not choose.

The refusal has two causes, and its remedy names the one that applies:

1. **The directory is no project yet.** Run `ipe init` in it, which writes a
   `package.ipe` and a `src/Main.ipe` to start from — or, if the project lives
   elsewhere, change into the directory that holds its `package.ipe` and run
   ipe from there, or pass that directory as the argument.
2. **The directory is a project's `src/` or `tests/`** (for example
   `ipe type-check tests`). It holds the project's modules, not a project, so
   `ipe init` there would nest a second project inside the first. Run ipe from
   the project directory — the parent that holds `package.ipe` — or name a
   module file instead, such as `ipe type-check tests/Main.ipe`.

If the directory holds a legacy `ipe.toml`, ipe says so instead: move its
settings into a `package.ipe`.

Nothing in your source has to change. Once `package.ipe` exists, this
`src/Main.ipe` builds:

```ipe
module Main exposing (main)

import Ipe.Io as Io

main : Task ()
main =
    Io.println "hello"
```

A program with a top-level value builds the same way:

```ipe
module Main exposing (main)

import Ipe.Io as Io

greeting : String
greeting = "hello"

main : Task ()
main =
    Io.println greeting
```

So does one that imports more of the standard library:

```ipe
module Main exposing (main)

import Ipe.Io as Io
import Ipe.String as String

count : Int
count = 41 + 1

main : Task ()
main =
    Io.println (String.fromInt count)
```
