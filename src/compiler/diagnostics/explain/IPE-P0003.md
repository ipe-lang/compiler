# IPE-P0003: input nests too deeply

Your code nests expressions inside one another more deeply than Ipe is
willing to follow. I stopped on purpose: there is a fixed limit on how
many layers of nesting I'll descend through, and this file went past
it.

This bound is deliberate, not a flaw. A parser that recurses without a
ceiling can be driven to exhaust the stack and crash the whole
compiler — so Ipe caps the depth and reports it cleanly instead of
risking a hard crash. In practice, real hand-written code never comes
close to the limit; hitting it usually means either generated code or
an accidental run of unbalanced brackets that keeps "opening" without
ever closing.

A tower of parentheses like this climbs the depth quickly:

```ipe
value =
    ((((((((((1))))))))))
```

Most of those parentheses do nothing — drop them:

```ipe
value =
    1
```

Deeply chained expressions are clearer when you give the intermediate
steps names with `let`, which also keeps the nesting shallow:

```ipe ipe:skip
result =
    let
        a = step1 input
        b = step2 a
    in
    step3 b
```

A long flat sequence counts too: each statement of a `do` block, each
`let` binding, each `else if` and each operator of a chain like
`a + b + c` nests the rest one level deeper once compiled. For such a
sequence the error covers the whole of it, from its first statement,
binding or operand up to the point where it went past the limit, so
you can see exactly which run to split.

The limit is fixed. If you genuinely need deeper nesting (for example,
machine-generated source), split the sequence into smaller named
functions or `let` bindings as above — flattening the structure almost
always makes the code easier to read too.
