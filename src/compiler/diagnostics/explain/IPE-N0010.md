# IPE-N0010: value defined more than once

You defined two top-level values with the same name in this module. I point at both: the one I am reporting and, as a secondary note, the first one I saw. Only one definition can own a name, so having two is ambiguous — I will not silently pick the last one and discard the other.

To fix this, rename one of them, or merge the two definitions into a single one if they were meant to be the same thing.

Here the name `total` is defined twice:

```ipe ipe:error
total : Int
total = 10

total : Int
total = 20
```

Rename one of them so each definition has its own name:

```ipe
subtotal : Int
subtotal = 10

total : Int
total = 20
```

If the two were really meant to be one value, keep a single definition:

```ipe
total : Int
total = 30
```

The same code fires when a local value's name collides with one brought in by an EXPLICIT import (`exposing (name)`) — that clash is refused right here, at the declaration, exactly like two local duplicates. A name shared only with an OPEN import (`exposing (..)`) is different: it defers to the first bare use instead (see IPE-N0024).

The same code also fires when a record TYPE lists one field label twice, as in `{ name : String, name : Int }`: a record has one field per label, so the second `name` is refused at the type, naming the duplicated label. Remove the repeated label, or rename it if the two fields were meant to differ.
