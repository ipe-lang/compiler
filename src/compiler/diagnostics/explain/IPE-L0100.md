# IPE-L0100: pattern kind not supported yet

You wrote a `case` branch whose pattern is a wildcard, a variable, or a
literal. Ipe can read it, but this version of the compiler cannot lower
it yet — for now a `case` may only match on **nullary constructors**
(constructors that take no arguments), one branch per constructor.

This isn't a mistake in your code; it's a feature Ipe hasn't grown into
yet. Wildcard patterns (`_`), binding patterns (`other`), and literal
patterns (`0`, `"hi"`) are all on the roadmap, but right now you'll need
to spell out a branch for each constructor of the type you're matching
on.

`[feature: case-pattern-kinds]`

A wildcard branch is what trips this today:

```ipe ipe:skip a fragment; Light and Red are assumed from context
describe : Light -> String
describe light =
    case light of
        Red -> "stop"
        _ -> "go"
```

A literal pattern hits the same wall:

```ipe
label : Int -> String
label n =
    case n of
        0 -> "zero"
        other -> "many"
```

Until those land, enumerate every constructor explicitly — no catch-all
needed, because the compiler already checks that you covered them all:

```ipe
type Light
    = Red
    | Amber
    | Green

describe : Light -> String
describe light =
    case light of
        Red -> "stop"
        Amber -> "ready"
        Green -> "go"
```

This is a current limitation, not a wrong move on your part. If matching
on literals or wildcards matters for your work, please nudge us at
https://github.com/ipe-lang/compiler/issues so we can prioritise it.
