# IPE-F4412: an FFI cache artifact cannot be read or written

While managing the binding files for a foreign Rust crate, I hit a
filesystem problem: one of the four cache artifacts could not be read,
written, or deleted. The message names the exact path and the
operating-system error.

## The four artifacts

When `ipe add <crate>` succeeds, I write four files under the
project's `.ipe/cache/ffi/rust/` directory:

| File | What it is |
|---|---|
| `<crate>.ipei` | the typed interface — every binding's signature |
| `<crate>.kernel.json` | the call registry the compiler resolves against |
| `<crate>_bindings.rs` | the generated Rust glue that gets compiled in |
| `<crate>.coverage.md` | an honest report of what could *not* be bound, and why |

A warm `ipe dev build` reads these and never re-inspects the crate; only
an explicit `ipe add` or `ipe install` regenerates them, and
`ipe remove` deletes them.

Your program only sees the result — a module of typed bindings:

```ipe ipe:skip
import Rust.Semver as Semver

parse : String -> Result Error Version
parse raw =
    Semver.parse raw
```

When one of the four files cannot be touched, that import cannot be
made to work, so I stop with this code instead of half-writing a
cache:

```ipe ipe:skip
-- a half-written cache would be worse than none: the compiler could
-- type-check against an .ipei whose _bindings.rs never landed, and
-- the build would fail far from the real cause.
```

```ipe ipe:skip
-- the fix is always safe: the cache is derived, so
--   ipe install
-- rebuilds every artifact from scratch.
```

## What usually causes this

- the project directory is read-only, or owned by another user;
- the disk is full;
- a cache file was deleted or replaced by something unexpected (for a
  *corrupted* file the decode gate rejects it separately — this code
  is about the filesystem, not the contents);
- two processes are racing over the same cache.

## What to do

Check the path in the message: permissions, free space, ownership.
Then re-run `ipe install` to regenerate the cache from scratch — the
artifacts are derived files, always safe to rebuild.

## Glossary

- **artifact** — a file produced by a tool for later use. From Latin
  *arte factum*, "made by craft".
- **cache** — saved results of expensive work (here: inspecting and
  binding a crate) so the work is not redone on every build.
- **warm / cold** — a cache is *warm* when its contents are already
  present and usable, *cold* when it must be filled first.
