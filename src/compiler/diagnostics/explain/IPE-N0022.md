# IPE-N0022: name not exposed

You are importing a name from a module that exists, but that module does not expose the name you asked for. This happens when the `exposing (...)` list in your `import` statement asks for a value or type that the target module either does not define or has marked private.

Here `hiddenHelper` is not one of `Ipe.String`'s exports:

```ipe ipe:error
import Ipe.String exposing (fromInt, hiddenHelper)

label : String
label =
    fromInt 1
```

`Ipe.String` does not expose `hiddenHelper`. Remove it from the `exposing` list, or import only the names the module actually exports.

The same error fires for a type name the module does not define:

```ipe ipe:error
import Ipe.String exposing (Utf16)

label : String
label =
    "ok"
```

`Ipe.String` has no `Utf16` type; this is usually a spelling slip. Check the module's own `exposing` list for the name you meant.

Importing only the names the module actually exposes resolves cleanly:

```ipe
import Ipe.String exposing (fromInt)

label : String
label =
    fromInt 1
```

A constructor named in an `exposing` list but not exported by its type is handled differently: it is silently left out of scope rather than refused here, so using it unqualified later is IPE-N0003 ("cannot find this constructor"), not this code.

## Qualified types

The same holds for a qualified type: with `import Lib.Utils as U`, the annotation `U.Helper` is refused when `Lib.Utils` declares `Helper` but leaves it out of its `module Lib.Utils exposing (...)` list. Add `Helper` to that list, or use a type the module exposes. A type the module does not declare at all is IPE-N0005 instead.
