# IPE-E0013: host toolchain missing

The compiler translated your Ipe program to Rust, and the build then stopped
because the host is missing a toolchain component the build needs — not
because of a mistake in your code, and not a bug in the compiler.

The message names which component is missing and how to install it on your
host. It can be a host C compiler or linker (on macOS the Xcode Command Line
Tools, on Windows the MSVC Build Tools, on Linux a C compiler and its C library
development files), a Rust toolchain recent enough for the build, a target's
Rust standard library, or a C compiler for a musl target. The last three need
a word more:

- **The Rust toolchain is older than the release Ipe pins** — the crates Ipe
  emits declare the Rust release Ipe is built and tested with as their
  `rust-version`, and the build would use an older one. The message names
  both releases. With `rustup`, run `rustup update stable`, or install the
  pinned release with `rustup toolchain install <release>` and select it for
  the build with `RUSTUP_TOOLCHAIN=<release>`. `rustup` picks the toolchain
  per directory, so a `rust-toolchain.toml` or an override in your project
  does not reach a build whose output directory lies outside it.

- **A target's Rust standard library is not installed** — for example,
  building for `aarch64-unknown-linux-musl` without that target added to the
  Rust toolchain the build uses. With `rustup`, run `rustup target add
  <triple>`, or `rustup target add --toolchain <toolchain> <triple>` when the
  build uses a toolchain other than your default one; the message names the
  toolchain. A Rust toolchain not managed by `rustup` needs the target's
  standard library installed the way that toolchain was installed.
- **No C compiler can target the musl triple** — none was found, or the one
  found builds for another architecture or for glibc. When your machine has
  the same architecture as the target, install your distribution's musl
  package: Debian/Ubuntu `musl-tools`, Fedora `musl-gcc`, Arch `musl`, Alpine
  `build-base`. Those packages build only for your own architecture, so for a
  cross build (an `aarch64` target on an `x86_64` machine, say) install a musl
  cross compiler for that architecture and set `CC_<triple>` (the triple with
  underscores in place of dashes, e.g. `CC_aarch64_unknown_linux_musl`) to its
  path.

What to try:

1. **Install the component the message names**, with the command it shows.
2. Re-run the build; the diagnostic disappears once the host has everything
   the target needs.

Your Ipe program has nothing to fix — here is a valid program that builds
once the host toolchain is complete:

```ipe
module Main exposing (main)

import Ipe.Io as Io

main : Task ()
main =
    Io.println "hello"
```

A type-annotated variant also compiles fine:

```ipe
module Main exposing (main)

import Ipe.Io as Io

greeting : String
greeting = "hello"

main : Task ()
main =
    Io.println greeting
```

There is nothing to change in your source — just complete the host toolchain
and try again:

```ipe
module Main exposing (main)

import Ipe.Io as Io
import Ipe.String as String

count : Int
count = 41 + 1

main : Task ()
main =
    Io.println (String.fromInt count)
```
