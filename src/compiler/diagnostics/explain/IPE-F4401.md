# IPE-F4401: a foreign binding's inspection data is malformed

While reading the inspection data for a Rust crate binding, I met a
value I do not recognise — for example an unknown effect kind, an
identifier that is not a legal Rust name, or a type reference carrying
two contradictory discriminators. I stopped rather than guess.

## Where this data comes from

`ipe add <crate>` runs an inspector over the crate and stores what it
found as structured data. Everything you later call from Ipê is checked
against that data:

```ipe ipe:skip illustrates calling a Rust crate binding, not a runnable program here
import Rust.Uuid as Uuid

main =
    println Uuid.newV4
```

The data is a contract between the inspector and the compiler. Every
field has a small closed set of legal values — an effect is `pure`,
`fallible`, or `effectful`; a receiver is passed by `ref`, `refmut`, or
`value`; an identifier must look like a Rust identifier. An unknown
value means the data was produced by a different tool version, was
corrupted, or was edited by hand.

## Why guessing would be worse

Suppose I met an unknown effect kind and silently defaulted it to
`pure`. A function that actually performs I/O would then be callable
outside `Task`, and your program would perform side effects where the
types promise none:

```ipe ipe:skip illustrates a hypothetical mis-classified binding, not Ipe source to check
-- if `Rust.SomeCrate.writeThing` were mis-classified as pure,
-- this innocent-looking expression would write to disk:
label = Rust.SomeCrate.writeThing "data"
```

Refusing malformed data keeps the type system honest at the foreign
boundary. An identifier check matters even more: a "function name" that
is not a legal Rust identifier would be spliced into generated source,
which is exactly the injection shape this check exists to kill.

## What to do

Regenerate the binding so the data is rewritten by the current tools:

```ipe ipe:skip illustrates the shell commands to regenerate the binding, not Ipe source
-- from your project directory:
--   ipe remove <crate>
--   ipe add <crate>
```

If regeneration still fails, the inspector and the compiler disagree
about the data contract — please report it with the crate name, the
crate version, and the exact message.
