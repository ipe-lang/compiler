# IPE-L0132: Ui.cells is terminal-only and not available in the Web/WebView shape

`Ui.cells` paints a **raw character grid** straight onto the terminal — a rows-of-
characters island you can drop inside an otherwise-structured `Ipe.Ui` view. It
exists so a `Terminal` app can hand-paint a region (a hexdump, a sparkline, a
game board) cell by cell, keeping the rest of the screen laid out by the normal
`Ui.el` / `Ui.row` / `Ui.column` builders.

Because it writes directly to terminal cells, it has **no meaning in a browser**:
there is nothing to paint a raw cell grid onto in the `Web` or `WebView` shape.
Using it there is rejected here, at compile time, rather than emitting Rust that
would fail to build after `ipe dev build` already reported success.

```ipe ipe:error
module Main exposing (main)

import Ipe.Tea.Web as Web
import Ipe.Tea.Web.Cmd as Cmd
import Ipe.Tea.Web.Sub as Sub
import Ipe.Ui as Ui exposing (Element)

type alias Model = { count : Int }

type Msg = NoOp

init : WebReq -> ( Model, Cmd.Cmd Msg )
init _req =
    ( { count = 0 }, Cmd.none )

update : Msg -> Model -> ( Model, Cmd.Cmd Msg )
update _msg model =
    ( model, Cmd.none )

subscriptions : Model -> Sub.Sub Msg
subscriptions _model =
    Sub.none

view : Model -> Element Msg
view model =
    -- rejected: `Ui.cells` under `Web.tea` (the Web shape has no terminal grid)
    Ui.cells [ [ 'h', 'i' ] ]

main =
    Web.tea
        { init = init
        , update = update
        , view = view
        , subscriptions = subscriptions
        , routes = []
        , notFound = { count = 0 }
        }
```

## How to fix

**Use a cell grid only under the `Terminal` shape.** A full-screen terminal app
(`Tui.tea`) renders a `Screen` tree, so a `Cells.cells` island
composes with the rest of the view:

```ipe
module Main exposing (main)

import Ipe.Tea.Tui as Tui
import Ipe.Tea.Tui.Cmd as Cmd
import Ipe.Tea.Tui.Sub as Sub
import Ipe.Ui.Cells as Cells exposing (Screen)

type alias Model = { count : Int }

type Msg = NoOp

init : () -> ( Model, Cmd.Cmd Msg )
init _unit =
    ( { count = 0 }, Cmd.none )

update : Msg -> Model -> ( Model, Cmd.Cmd Msg )
update _msg model =
    ( model, Cmd.none )

subscriptions : Model -> Sub.Sub Msg
subscriptions _model =
    Sub.none

view : Model -> Screen Msg
view model =
    -- accepted: `Cells.cells` inside a `Tui.tea` view
    Cells.column []
        [ Cells.text "hexdump:"
        , Cells.cells [ [ '4', '8', ' ', '6', '9' ] ]
        ]

main =
    Tui.tea
        { init = init
        , update = update
        , view = view
        , subscriptions = subscriptions
        }
```

**If you need this content in the browser**, render it with the normal UI
builders instead — a grid of characters is just text, so `Ui.text` (or a
`Ui.column` of rows) shows the same content in every shape:

```ipe ipe:skip a fragment; Model and Msg are assumed from context
-- accepted in every shape: plain text instead of a raw cell grid
view : Model -> Element Msg
view model =
    Ui.text "48 69"
```

## Why this happens

The `Web` and `WebView` shapes render `Element msg`; `Tui.tea` and `Cli.tea`
render the distinct terminal view type `Screen msg`. Each shape can only
render the primitives its runtime backend understands. `Ui.cells` is a
terminal-backend primitive: it lowers to a direct cell paint against the
terminal's frame buffer. The Web and WebView backends emit a browser DOM and
have no such buffer, so a `Ui.cells` reference in a web-family program is
inadmissible. The compiler proves the shape from the app entry point
(`Web.tea` / `WebView.app` versus `Tui.tea` / `Cli.tea`)
and fails closed the moment a terminal-only node appears in a web-family build.
