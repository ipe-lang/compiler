# IPE-N0030: server module reachable from the wasm client entry

[IPE-N0029](IPE-N0029.md) stops a *single kernel* from having a meaning in a
wasm build. This error is the compositional version of the same idea: it
walks every module your client entry can reach — through imports, through
the modules those modules import, and so on — and stops if that walk ever
lands on a module that itself names a server-only kernel somewhere inside
it, even indirectly.

Think of your program as a map of modules connected by imports. Your `--target
wasm` entry point is the starting pin. The compiler walks every road out from
that pin. If one of those roads leads to a module that uses `Ipe.Db`, or
`Auth.signToken`, or any other server-only effect, the walk stops there and
reports the exact path it took to get there — not just "somewhere in this
program", but the precise chain of modules, e.g.:

```
Main(client) -> View(shared) -> Data(server: imports Ipe.Db.query)
```

Read that as: `Main` imports `View`, `View` imports `Data`, and `Data` is
the module that actually names the server-only kernel. `Data` is classified
`server`; `Main` and `View` are `shared` (the default — a module earns the
`server` label only by directly naming a server-only kernel itself).

A concrete example: a `view` module shared between your server-rendered page
and your wasm client accidentally imports a helper that queries the
database directly instead of going through an HTTP endpoint:

```ipe ipe:error
-- Data.ipe
loadUser : Int -> Task Error User
loadUser id =
    Db.query "select * from users where id = ?" [SqlInt id]

-- View.ipe
import Data

view model =
    -- ships into the client bundle...
    ...

-- Main.ipe (the --target wasm entry)
import View
```

Even though `Main`'s own code never calls `Db.query`, `View` imports `Data`,
which does — so the walk from `Main` reaches a server module, and this error
fires naming that exact chain.

The fix is the same architectural move as IPE-N0029: split the database
access out from behind the shared `view`, run it on a server, and reach it
over HTTP from the client:

```ipe ipe:skip
-- server (native target)
main =
    Server.listen 8000
        [ Server.get "/api/user/:id" getUserHandler ]

-- client (wasm target)
update msg model =
    case msg of
        Refresh ->
            ( model, Cmd.perform (Http.get "/api/user/1") GotUser )
```

With the data fetched on the server, the shared `view` stays client-safe: it
takes the already-loaded data as an argument instead of reaching for it, so it
names no server-only kernel and the walk from your wasm entry never lands on a
`server` module:

```ipe ipe:skip
-- View.ipe — shared, browser-safe: no Db, no server kernels
view : User -> Element Msg
view user =
    Ui.text ("Hello, " ++ user.name)
```

## Glossary

- **module classification** — every module linked into a build is either
  `shared` (the default) or `server` (it directly names a kernel with no
  browser denotation). A module earns `server` by USING a server-only
  kernel, not by being imported by one.
- **reachability closure** — the full set of modules transitively reachable
  from the client entry point by following imports. Only this set matters
  for IPE-N0030 — a `server` module your client entry never imports, even
  transitively, is not an error.
- **client entry** — the module `ipe dev build --target wasm` starts compiling
  from (the entry file, or `Wasm.entry` in `package.ipe` when set).
