# IPE-N0030: server module reachable from the wasm client entry

[IPE-N0029](IPE-N0029.md) stops a *single kernel* from having a meaning in a
wasm build. This error is the compositional version of the same idea: it
follows every definition your client entry can reach — the functions `main`
uses, the functions those use, across modules — and stops if that walk
lands on a definition in another module that names a server-only kernel.
A definition the entry never reaches is not shipped, so it is never an error.

Think of your program as a map of definitions connected by uses. Your `--target
wasm` entry point is the starting pin. The compiler walks every road out from
that pin. If one of those roads leads to a definition that uses `Ipe.Db`, or
`Auth.signToken`, or any other server-only effect, the walk stops there and
reports the exact path it took to get there — not just "somewhere in this
program", but the precise chain of modules, e.g.:

```
Main(client) -> View(shared) -> Data(server: imports Ipe.Db.query)
```

Read that as: `Main` uses a definition of `View`, which uses one of `Data`,
and that `Data` definition actually names the server-only kernel. `Data` is
labelled `server`; `Main` is the `client` entry and `View` is `shared` (a
module on the path that does not itself name the kernel).

A concrete example: a `view` module shared between your server-rendered page
and your wasm client accidentally imports a helper that queries the
database directly instead of going through an HTTP endpoint:

```ipe ipe:error
-- Data.ipe
loadUser : Int -> Task Error User
loadUser id =
    Db.query "select * from users where id = ?" [SqlInt id]

-- View.ipe
import Data

view model =
    -- ships into the client bundle...
    ...

-- Main.ipe (the web client entry)
import View
```

Even though `Main`'s own code never calls `Db.query`, once `view` calls
`Data.loadUser` the walk from `Main` reaches it, and this error fires naming
that exact chain. An import alone, with no reached use, ships nothing.

The fix is the same architectural move as IPE-N0029: split the database
access out from behind the shared `view`, run it on a server, and reach it
over HTTP from the client:

```ipe ipe:skip
-- server (native target)
main =
    Server.listen 8000
        [ Server.get "/api/user/:id" getUserHandler ]

-- client (wasm target)
update msg model =
    case msg of
        Refresh ->
            ( model, Cmd.perform (Http.get "/api/user/1") GotUser )
```

With the data fetched on the server, the shared `view` stays client-safe: it
takes the already-loaded data as an argument instead of reaching for it, so it
names no server-only kernel and the walk from your wasm entry never lands on a
`server` module:

```ipe ipe:skip
-- View.ipe — shared, browser-safe: no Db, no server kernels
view : User -> Element Msg
view user =
    Ui.text ("Hello, " ++ user.name)
```

## Glossary

- **module labels** — in the reported chain the entry is `client`, the
  module holding the reached definition that names a kernel with no browser
  denotation is `server`, and every module in between is `shared`. A
  module's other, unreached definitions never earn it a label.
- **reachability closure** — the definitions transitively reachable from
  the client entry's `main` by following uses. Only this set is judged and
  emitted — a server-only kernel your client entry never reaches, even
  transitively, is not an error.
- **client entry** — the module `ipe dev build web client` starts compiling
  from (the entry file, or `Wasm.entry` in `package.ipe` when set).
