# IPE-F4416: two foreign crates map to one module slug

Every installed Rust crate lives in the emitted program under one module
named by its slug: the package name lowercased, with every character
outside `a-z` and `0-9` turned into `_`. Two different package names can
fold to the same slug — `a-b` and `a_b` both become `a_b`. The crate you
are adding maps to a slug another installed crate already holds, so the
add stopped before it overwrote that crate's cache.

Each installed crate is imported under its own module:

```ipe ipe:skip illustrates calling a Rust crate binding, not a runnable program here
import Rust.AB as AB

greeting = AB.hello "world"
```

The message names the slug, the crate already installed under it, and
the crate you tried to add.

## What to do

Keep one of the two crates. Remove the installed one first if you want
the new one instead:

```ipe ipe:skip illustrates the shell commands, not Ipe source
-- ipe rust remove a-b
-- ipe rust add a_b
```

Reinstalling the same crate is never refused: a slug held by the same
package name is overwritten in place.

```ipe ipe:skip illustrates the shell command, not Ipe source
-- ipe rust add a-b
```

## Why this is a hard error

Two crates under one module would collide in the emitted Rust: one
crate's wrappers would replace the other's, and calls bound to the first
would silently run the second. Refusing at install keeps every slug owned
by exactly one crate, and the build refuses the same collision again if
a cache ever holds two crates of one slug.

## Glossary

- **slug** — the module name an installed crate is emitted under in the
  generated Rust, derived from its package name.
- **package name** — the crate's name on crates.io or in its
  `Cargo.toml`, such as `serde_json`.
