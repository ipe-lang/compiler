# IPE-F4416: a foreign crate cannot take its module slug

Every installed Rust crate lives in the emitted program under one module
named by its slug, folded from its package name: lowercased, with every
character outside `a-z` and `0-9` turned into `_`, a leading digit
prefixed with `_`, and a `_` appended to a Rust keyword or to a name that
already ends in `_` (`Match` becomes `match_`). The crate you are adding
could not take its slug, so the add stopped before anything was written
to the cache. There are two causes.

Each installed crate is imported under its own module:

```ipe ipe:skip illustrates calling a Rust crate binding, not a runnable program here
import Rust.AB as AB

greeting = AB.hello "world"
```

## Another crate holds the slug

Two different package names can fold to the same slug: `a-b` and `a_b`
both become `a_b`. The message names the slug, the crate already
installed under it, and the crate you tried to add. Keep one of the two
crates. Remove the installed one first if you want the new one instead:

```ipe ipe:skip illustrates the shell commands, not Ipe source
-- ipe rust remove a-b
-- ipe rust add a_b
```

Reinstalling the same crate is never refused: a slug held by the same
package name is overwritten in place.

```ipe ipe:skip illustrates the shell command, not Ipe source
-- ipe rust add a-b
```

When the cached record under the slug does not decode, the message says
so instead of naming a crate. `ipe rust remove` with the name you are
adding deletes that record, and the add then succeeds.

## The name folds to no legal slug

A package name in the `ipe_asserted` namespace, which the compiler keeps
for its own call shims (`ipe-asserted-x` folds to `ipe_asserted_x`), has
no slug. No crate with such a name can be installed; bind it through a
local wrapper crate with another name.

## Why this is a hard error

Two crates under one module would collide in the emitted Rust: one
crate's wrappers would replace the other's, and calls bound to the first
would silently run the second. A crate in the shim namespace could pose
as the compiler's own shims. Refusing at install keeps every slug owned
by exactly one crate, and the build refuses the same collision again if
a cache ever holds two crates of one slug.

## Glossary

- **slug** — the module name an installed crate is emitted under in the
  generated Rust, derived from its package name.
- **package name** — the crate's name on crates.io or in its
  `Cargo.toml`, such as `serde_json`.
