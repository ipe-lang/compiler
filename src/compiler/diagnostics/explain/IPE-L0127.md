# IPE-L0127: a value holding a function is used more than once

A binding whose type embeds a function — a bare function value, or one held
inside a `Maybe` / `Result` / user-union constructor payload — was used more
than once in a value-CONSUMING (non-call) position, and the compiler could not
prove the value safe to duplicate.

The Rust backend lowers a Ipe function value to `Box<dyn Fn(..) -> R + Send +
Sync + 'static>`. That type does not implement `Clone`, so it can be moved
exactly once. **Calling** the value is unlimited — `Fn::call` takes `&self`, so
it only borrows — but a second use that is not a direct call (storing it again,
passing it to another function, returning it a second time) would move an
already-moved value, which `cargo` rejects as E0382.

```ipe ipe:skip a fragment; callSecond is assumed from context
-- before (IPE-L0127 — `mf` is forwarded twice)
consumeTwice mf =
    ( callSecond mf, callSecond mf )
```

## How to fix

**Call the function at each use site** instead of forwarding the wrapping
value more than once — calling is unlimited:

```ipe
-- after (both calls happen through ONE extraction — accepted)
callTwice mf =
    case mf of
        Just f ->
            f 1 + f 2

        Nothing ->
            0
```

**Re-construct the value at each use** when the underlying function is cheap
to rebuild (e.g. a top-level named function referenced bare):

```ipe ipe:skip a fragment; consume is assumed from context
inc n =
    n + 1

-- after (two independent constructions, each used once)
useTwice =
    ( consume (Just inc), consume (Just inc) )
```

**Restructure the code to a single linear use** — thread the value through
one call chain rather than branching it into two independent consumers.

## Why this happens

`Box<dyn Fn(..) -> R + Send + Sync + 'static>` is the only sound Rust
representation for a first-class Ipe function value (it may capture arbitrary
state), and `Box<dyn Fn>` is not `Clone`.

A closed record-of-functions that (a) never escapes its defining function and
(b) never flows into a polymorphic position and (c) has every non-function
field `Clone` is promoted automatically: its function fields ride the
`Clone` `Arc<dyn Fn>` carrier, so the record duplicates by refcount bump and is
freely reusable. This gate fires only for the cases that remain outside that
proof.

## What remains fail-closed

- A bare function value (`a -> b`) reused as a value more than once.
- A `Maybe (a -> b)` / `Result e (a -> b)` / user-union payload reused WITHOUT
  first extracting the function at a pattern match (extract-then-call is
  accepted — the extracted bare function rides the reuse-promotion path).
- A record-of-functions that ESCAPES its defining function (is returned,
  stored in a larger structure, or passed onward across a function boundary),
  or flows into a `Generic`/polymorphic parameter — the containment proof fails.
- A record-of-functions with a non-`Clone` non-function field (a
  `Task`/`Cmd`/`Sub`/`Decoder`/opaque handle) — the whole value cannot be made
  `Clone`, so it cannot be duplicated for reuse.
