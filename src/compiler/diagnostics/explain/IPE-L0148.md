# IPE-L0148: a JS port boundary value is not seal-legal (a secret/sink, an untyped Value, or a non-plain type cannot cross to JS)

A **port** is the raw typed channel between an Ipê app and the JavaScript on its
page: `Js.send` carries a value out to JavaScript, and `Js.subscribe` receives a
value coming in. Every value crossing that channel must be **sealable** — a
plain, closed, concrete value type that can be safely turned into JSON and back.

This error means a value you tried to send or receive is **not** sealable.

## Why a value is turned away

A value is refused when it is any of these:

- A **secret** or a security-sink type — a `Secret`, or a `Url`, `Path`, `Dsn`,
  `SqlFragment`, `Regex`, or a key/MAC. A secret must **never** leave the program
  as JSON: that would hand it to page JavaScript, which is outside your control.

```ipe ipe:skip a fragment; `Msg` is assumed from context
-- Reject: a Secret must never be serialised to JavaScript.
sendToken : Secret -> Cmd Msg
sendToken token =
    Js.send token
```

- An **untyped `Value`** — an anything-goes JSON hole. The port channel cannot be
  spelled with `Value`, on purpose: an undecoded blob must never travel inward.

```ipe ipe:skip a fragment; `Msg`, `valueDecoder`, and `GotAnything` are assumed from context
-- Reject: an untyped Value cannot cross the port.
badIn : Sub Msg
badIn =
    Js.subscribe valueDecoder GotAnything
```

- A **function**, an **effect** (`Cmd` / `Sub` / `Task` / `Decoder`), a **view**
  value, or another opaque handle — none of these is a plain serialisable value.

This is exactly the same rule the visual-widget boundary (`CustomElement down up`)
uses. The port just applies it to the value you send or the value your decoder
produces.

## How to fix

Send and receive **plain declared data**, and give any genuinely free-form
payload a **name** instead of leaving it untyped:

```ipe ipe:skip a fragment; `Msg`, `rawJsonDecoder`, and `GotRawJson` are assumed from context
type RawJson
    = RawJson String

goodIn : Sub Msg
goodIn =
    Js.subscribe rawJsonDecoder GotRawJson
```

For a secret, keep it on the Ipê side of the seam: send only the *result* of
using it (a plain value), never the secret itself.

## Glossary

- **seal** — the rule that a value crossing to or from JavaScript must be a plain,
  closed, concrete value type. Named after sealing an envelope: what goes across is
  fixed and inspectable, with no hidden opening.
- **sink type** — a value (like `Secret` or `SqlFragment`) whose whole point is to
  be handled carefully at one boundary; serialising it elsewhere would defeat that
  care.
- **fail closed** — when a value cannot be proven safe to cross, refuse it rather
  than guess. Here: refuse a payload the seal cannot accept.
