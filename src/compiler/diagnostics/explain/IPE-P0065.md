# IPE-P0065: a `do` block must contain at least one Task step

<!-- illustrative-only: all code blocks below are Ipê source syntax, not runnable shell commands -->

A `do` block is Task sequencing sugar. Every block must contain at least one
real Task step — a `<-` bind that runs a `Task` and names its result, or a
bare-run line that runs a `Task` for its effect:

```ipe
import Ipe.Io as Io
import Ipe.Task as Task

main : Task Error ()
main =
    do
        x <- Io.readLine ()    -- `<-` : a real Task step
        Io.println x           -- bare : another real Task step
```

A block whose **every** statement is a `=` pure-let binding is pure code
dressed as `do`. It has no Task step at all, so the compiler rejects it:

```ipe ipe:error
main : Task Error ()
main =
    do
        x = 1          -- `=` : a pure bind, no Task
        y = x + 1      -- `=` : still pure, still no Task
```

## How to fix it

**For pure binding — use `let … in`:**

```ipe
compute : Int
compute =
    let x = 1
    in
    x + 1
```

`let … in` is Ipê's form for pure sequential binding. `do` is reserved for
Task sequencing; they are disjoint by design.

**If a `Task` result is genuinely needed — wrap with `Task.succeed`:**

```ipe
import Ipe.Task as Task

compute : Task Error Int
compute =
    let x = 1
    in
    Task.succeed (x + 1)
```

**For concurrent fan-out — bind `Task.parallel` inside a real `do`:**

```ipe
import Ipe.Io as Io
import Ipe.Task as Task
import Ipe.String as String

checkA : Task Error String
checkA = Task.succeed "a"

checkB : Task Error String
checkB = Task.succeed "b"

checkC : Task Error String
checkC = Task.succeed "c"

main : Task Error ()
main =
    do
        results <- Task.parallel [ checkA, checkB, checkC ]
        Io.println (String.join ", " results)
```

## Why this rule exists

`do` and `let … in` are deliberately disjoint:

- `let … in` = pure binding. No effects, ever.
- `do` = Task sequencing with at least one real step.

A stepless `do` compiles today but writes tomorrow's confusion: it looks like
an effect block, yet nothing effectful happens. Rejecting it at parse time
makes the boundary between pure code and effectful code visible in the source,
without relying on types alone.

## Glossary

- **Task step** — a `<-` bind (`result <- task`) or a bare-run line (`task`)
  that actually sequences an effect into the chain. A `=` pure bind is not a
  Task step.
- **`Task.parallel`** — runs a list of tasks concurrently and collects their
  results in order. Use it with `results <- Task.parallel [...]` inside a `do`
  for fan-out.
- **`Task.succeed`** — lifts a pure value into a `Task` that immediately
  returns it with no effect.
