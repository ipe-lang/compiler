# IPE-P0070: source file is too large to compile

Every token and syntax node the compiler produces records its position as a byte
offset into the source file. Those offsets are stored as 32-bit numbers, so a
single source file may be at most `u32::MAX` (4,294,967,295) bytes — a little
under 4 GiB. A file larger than that cannot be given accurate spans, so instead
of clamping offsets (which would misreport every position past the limit and
point diagnostics at the wrong place) the compiler turns the file away up front.

This limit is far above any hand-written module; reaching it almost always means
a generated or accidentally-concatenated file.

```ipe ipe:skip a file that actually exceeds u32::MAX bytes cannot be held in a test fixture
module Generated exposing (table)

-- ...several gigabytes of machine-generated definitions in one file...
table =
    [ entry0, entry1, entry2 {- , … millions more … -} ]
```

A single module holding gigabytes of generated data exceeds the addressable span
range, so the compiler refuses it before parsing.

## To fix

Split the module into several smaller modules, each under the size limit, and
import between them:

```ipe
module Generated.Part1 exposing (part1)

entry0 = 1
entry1 = 2
entry2 = 3

part1 =
    [ entry0, entry1, entry2 ]
```

If the file is machine-generated, generate it in parts, or generate a thinner
representation that the program builds up at runtime:

```ipe ipe:skip illustrates importing between two sibling modules; a single fenced block names only one module
module Generated exposing (table)

import Generated.Part1 exposing (part1)
import Generated.Part2 exposing (part2)

table =
    part1 ++ part2
```
