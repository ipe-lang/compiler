# IPE-F4402: a foreign function declares contradictory shape flags

The inspection data for one function of a Rust crate binding claims the
function is two different things at once — for example both a record
field *getter* and an enum variant *constructor*. Those shapes are
mutually exclusive, so I dropped this one binding and kept the rest of
the crate.

## What shape flags are

Besides plain functions, a crate binding exposes several synthetic
helpers, each with its own generated form: field getters and setters,
enum variant constructors, tag readers, and payload extractors. In Ipê
they all look like ordinary functions:

```ipe ipe:skip illustrates calling a Rust crate binding, not a runnable program here
import Rust.Semver as Semver

major : String -> Int
major v =
    Semver.majorFromVersion (Semver.parse v)
```

Internally each helper carries exactly one shape, because each shape
generates different Rust. A getter reads a field; a constructor builds
a value; a tag reader inspects a variant:

```ipe ipe:skip illustrates the one-shape-per-helper rule as prose, not Ipe source
-- one shape per helper:
--   majorFromVersion   : Version -> Int          (field getter)
--   prerelease         : String -> Version       (variant constructor)
--   tagOfVersionKind   : VersionKind -> String   (tag reader)
```

## Why I drop the one binding instead of failing the crate

Two shape flags set on the same function is contradictory data — I
cannot know which body to generate, and generating the wrong one would
compile into wrong behaviour. The sound options are to refuse the whole
crate or to skip just the contradictory entry. Skipping only the entry
is strictly better: every other binding in the crate is unaffected, and
the coverage report tells you what was skipped and why.

The practical effect is that one name is missing from the module:

```ipe ipe:skip illustrates the effect of a dropped binding, not a runnable program here
import Rust.SomeCrate as SomeCrate

-- if `weirdHelper` was the dropped entry, this line now fails
-- name resolution — the rest of SomeCrate still works:
x = SomeCrate.weirdHelper 1
```

## What to do

Regenerate the binding (`ipe remove <crate>` then `ipe add <crate>`).
If the contradiction persists on a fresh inspection, the inspector
mis-classified that function — please report it with the crate name,
version, and the function named in the message.
