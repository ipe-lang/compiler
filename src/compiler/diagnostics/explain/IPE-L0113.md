# IPE-L0113: constructor used as a function value not supported yet

A data constructor that carries a payload was used as a first-class
function *value* — referenced bare, or applied to fewer arguments than it
declares — rather than applied to all of its fields at once. A *saturated*
construction is supported; a constructor passed around as a function, or
partially applied, is not yet.

A constructor like `Som : a -> Opt a` is, in principle, a function. Turning
it into a value needs the same machinery as passing any partially-applied
function around, which is a later milestone. For now, apply a constructor
to every field on the spot.

## Bare reference

Passing `Som` itself as a function value is not supported yet:

```ipe
type Opt a = Som a | Non

wrapAll : (Int -> Opt Int) -> Opt Int
wrapAll f = f 1

main = wrapAll Som          -- constructor as a value: not yet
```

## Partial application

`Node` declares three fields; applying it to two leaves a function:

```ipe
type Tree = Leaf | Node Tree Int Tree

main =
    let half = Node Leaf 1 in   -- partially applied: not yet
    half Leaf
```

## Saturated construction works today

Apply the constructor to all of its fields in one call:

```ipe ipe:skip the fully-applied constructor that compiles; shown without running the checker
type Tree = Leaf | Node Tree Int Tree

build : Tree
build = Node Leaf 1 Leaf       -- all fields supplied: OK

main = println "ok"
```

`[feature: ctor-as-function]`

This is a current limitation of the Ipe Rust compiler, not a problem with
your code. If constructor-as-function matters to your project, please tell
us at https://github.com/ipe-lang/compiler/issues.
