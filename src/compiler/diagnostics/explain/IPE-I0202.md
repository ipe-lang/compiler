# IPE-I0202: ICE: cross-module type-name collision

Sorry — while generating Rust, the backend found two types from different
modules that wanted the exact same Rust name. It can't emit both under one
name, so it stopped. Keeping names from separate modules apart is the
compiler's job, and a clash here means that name-mangling step didn't keep
them distinct.

This is a bug in the Ipe Rust compiler, not a mistake in your code. You're
free to reuse a type name like `Item` or `User` across modules — Ipe is
supposed to disambiguate them behind the scenes — so a collision at this
stage is ours to resolve, not yours.

Two modules can legitimately define a type with the same name:

```ipe ipe:skip illustrates one of two colliding modules in isolation, not a runnable program here
module Cart exposing (Item)

type Item
    = Book
    | Pen
```

```ipe ipe:skip illustrates the other of two colliding modules in isolation, not a runnable program here
module Menu exposing (Item)

type Item
    = Soup
    | Salad
```

And a program may bring both into play — this should compile, with the two
`Item` types kept separate internally:

```ipe
module Main exposing (main)

import Ipe.Io as Io

main : Task ()
main =
    Io.println "two modules, two Items, no clash"
```

This is a bug in the Ipe Rust compiler — not your fault. Please report it
(with this source + `ipe version`) at

https://github.com/ipe-lang/compiler/issues

so we can tighten the name-mangling.
