# IPE-L0154: a higher-order kernel callback returns a function

A higher-order kernel such as `List.map`, `List.foldl`, `Dict.map`,
`Maybe.map2`, or `Result.andMap` calls its callback with exactly the arguments
it was declared with. If the callback's result is itself a function, each call
would leave a partial application behind. The kernel has no way to build one,
so the program is refused.

The type checker normally reports this first as IPE-T0014 (or IPE-T0001 when
the callback's result is already known to be a function). IPE-L0154 is the
second, independent check at lowering. It is keyed on the resolved kernel and
its solved type, so the hazard stays closed even when the first check is
bypassed.

```ipe ipe:skip the curried-callback shape IPE-L0154 flags; shown without running the checker
add a b =
    a + b

-- Reject: `add` takes two arguments, so each element becomes `Int -> Int`.
partials =
    List.map add [ 1, 2, 3 ]
```

```ipe ipe:skip the curried-callback shape IPE-L0154 flags; shown without running the checker
-- Reject: the curried lambda returns a function for every element.
adders xs =
    List.map (\n -> \x -> x + n) xs
```

## How to fix it

Apply the missing argument inside the callback, or use the kernel whose
callback takes every argument:

```ipe ipe:skip the fully-applied-callback fix; shown without running the checker
add a b =
    a + b

-- Accept: the callback returns a plain `Int`.
bumped =
    List.map (\x -> add x 1) [ 1, 2, 3 ]

-- Accept: `List.map2` passes both arguments at once.
sums =
    List.map2 add [ 1, 2, 3 ] [ 10, 20, 30 ]
```

A fold whose accumulator is a function is refused on the same grounds. Fold
over data instead and build the function afterwards.

`Task`, `Cmd`, `Sub`, and `Decoder` kernels box their callbacks, so they are
not subject to this check.
