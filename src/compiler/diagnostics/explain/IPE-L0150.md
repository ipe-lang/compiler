# IPE-L0150: a committed string literal cannot become a Secret

A `Secret` is Ipê's typed wrapper for a credential — an API key, a password, a
token. Its whole purpose is that the plaintext can never be printed, logged, or
serialised by accident: there is no `Display`, no `Debug` that shows it, no JSON
encoding. The one thing a `Secret` must ALSO never be is **written straight
into your source code**, because source is committed to version control, shared,
and copied — a credential in a source file is a credential already leaked.

This error means you passed a **quoted string literal** to `Secret.fromString`.
The literal is a value baked into the program text, so it would ship the secret
inside the compiled binary and inside every copy of the repository.

```ipe ipe:skip the committed-literal shape IPE-L0150 flags; shown without running the checker
-- Reject: the API key is committed to source.
key : Secret
key =
    Secret.fromString "sk_live_51H8xY2abc..."
```

## How to fix it

Read the secret from the **environment at runtime** instead. `App.fromEnvRequired`
returns a `Secret` directly and fails closed if the variable is missing or
empty, so the credential lives only in your deployment environment, never in
source:

```ipe ipe:skip the environment-sourced fix; shown without running the checker
import Ipe.App as App

key : Secret
key =
    App.fromEnvRequired "STRIPE_API_KEY"
```

If you genuinely hold a plaintext the **program produced at runtime** — a value
read from a file, decoded from a request, or computed — you may seal that
runtime `String` with `Secret.fromString`. Only a source-text *literal* is
refused; a runtime `String` is accepted:

```ipe ipe:skip the runtime-string fix; shown without running the checker
import Ipe.Secret

-- Accept: `raw` is a runtime String (a function argument), not a literal.
seal : String -> Secret
seal raw =
    Secret.fromString raw
```

## Why the compiler refuses this

Under Ipê's first principle — Security — a secret must give an attacker no
foothold, and the safe outcome is the only reachable one (fail closed). A
committed credential is a leak that no amount of runtime redaction can undo, so
the compiler turns it away before it can be built rather than trusting you to
remember to remove it later. The check is at the single point where a plaintext
`String` becomes a `Secret` (`Secret.fromString`), which is the only place a
literal can cross into secret territory — every other `Secret`-typed position
already rejects a bare `String` as an ordinary type mismatch.
