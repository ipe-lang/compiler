# IPE-N0033: a Program may not import a managed-update-loop shape

Ipê has two kinds of runnable module. A **Program** is a plain `main : Task Error ()` — it runs an effect and exits, with no managed state and no view. A **TEA app** runs the managed `init` / `update` / `view` / `subscriptions` loop and comes in three shapes, each living under the `Ipe.Tea.*` namespace: `Ipe.Tea.Web`, `Ipe.Tea.WebView`, and `Ipe.Tea.Terminal`.

The rule is structural: **importing anything under `Ipe.Tea.*` marks a module a TEA app**, unless its `main` ends in a direct call of `Server.listen` (the server mount form below). So any other module with a plain `main` (a Program) that also imports a `Ipe.Tea.*` shape is a contradiction, and it is rejected here.

This Program trips the gate — its `main` is a `Task`, but it imports a shape:

```ipe ipe:skip
module Main exposing (main)

import Ipe.Io as Io
import Ipe.Tea.Web exposing (tea)

main : Task Error ()
main =
    Io.println "hello"
```

If you meant to write a Program, drop the `Ipe.Tea.*` import — a Program never needs one:

```ipe
module Main exposing (main)

import Ipe.Io as Io

main : Task Error ()
main =
    Io.println "hello"
```

If you meant to write a TEA app, make `main` a shape entry (`Web.tea`, `Tui.tea`, `Cli.tea`, or `WebView.app`) instead of a bare `Task`:

```ipe ipe:skip
module Main exposing (main)

import Ipe.Tea.Web exposing (tea)

main =
    app
        { init = init
        , update = update
        , view = view
        , subscriptions = subscriptions
        , routes = []
        , notFound = HomePage
        }
```

The view- and data-only modules `Ipe.Ui`, `Ipe.Html`, and `Ipe.Css` are deliberately **not** under `Ipe.Tea.*`: they are shape-agnostic data and static rendering, usable by a Program. Building a `Ui` tree and rendering it with a `Task` never trips this gate — only the live-loop machinery under `Ipe.Tea.*` does.

A server that mounts a web app is the one Program that may import `Ipe.Tea.Web`: it builds the app with `Web.embed` and mounts it with `Server.mountApp`, and its `main` ends in `Server.listen` itself. The embedded app is a value the server consumes, not the module's own shape. Only the head of `main`'s result counts — `Server.listen` called from a helper that `main` calls is not this form and is rejected here — so a helper that `main` calls may build the route list, but never the listen:

```ipe ipe:skip needs a full web app (init, update, view, routes) behind the config
module Main exposing (main)

import Ipe.Server.Http as Server
import Ipe.Tea.Web as Web

main : Task Error ()
main =
    Server.listen 8000 [ Server.mountApp "/" (Web.embed config) ]
```
