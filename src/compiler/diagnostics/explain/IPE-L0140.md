# IPE-L0140: a Debug.* escape hatch was used in a production build

`Debug.log` is a *development-only* tool. It prints a labelled value to
standard error and hands the value straight back, so you can drop it into the
middle of any expression to peek at what is flowing through:

```ipe ipe:skip
import Ipe.Debug as Debug

total =
    Debug.log "subtotal" subtotal + tax
```

While you are developing, that line prints `subtotal: 42` to stderr and the
program behaves exactly as if you had written `subtotal + tax`. The value is
untouched — `Debug.log` is a window, not a filter.

But a debugging window has no place in a shipped program: it writes to stderr
on a hot path, it can leak internal values, and it is almost always a leftover
you meant to remove. So when you run `ipe release`, the compiler refuses any
`Debug.*` use rather than silently stripping it (which would hide a real
leftover) or shipping it (which would leak).

This is the same discipline Elm applies to its own `Debug` module.

## How to fix it

**You are still developing.** Use `ipe dev build` or `ipe dev run` — these are
development builds and accept `Debug.log` freely. The following are
illustrative command forms (run from a project root with `src/Main.ipe`):

```sh
ipe dev build     src/Main.ipe  # development — Debug.log is allowed
ipe dev run       src/Main.ipe  # development — Debug.log is allowed
ipe release build src/Main.ipe  # production  — Debug.log is rejected
```

**You are shipping.** Remove the `Debug.log` call. It was never meant to
survive to production — that is the whole point of the escape hatch:

```ipe ipe:error
total =
    Debug.log "subtotal" subtotal + tax   -- before: a leftover debug window

total =
    subtotal + tax                        -- after: the window removed
```

**You actually want to log in production.** Reach for a real output kernel
instead of the debug window:

```ipe ipe:error
import Ipe.Io as Io

-- write a line to stderr as a Task
Io.eprintln ("subtotal: " ++ String.fromInt subtotal)
```

or, for structured/levelled observability, `Log.info` / `Log.error` from
`Ipe.Log`. Those are ordinary effects you are meant to keep.

## The `Debug._` catch-all pattern

The same gate applies to the development-only catch-all **pattern** `Debug._`.
It matches every remaining value in a `case` like `_`, but is exempt from the
closed-union catch-all error (IPE-T0018) so you can defer some variants while a
type is still growing. Like `Debug.log`, it is development-only: `ipe release`
rejects a reachable `Debug._` with this same error.

To ship, replace `Debug._` with an explicit arm per remaining constructor (or an
or-pattern `A | B ->` grouping the ones that share a body), so every variant is
handled and no future addition can fall through silently.

## Glossary

- **escape hatch** — a deliberate, marked exception to a rule. `Debug.log` is
  the one impure "just print it" hole in an otherwise effect-typed language;
  being marked lets the compiler gate it in production.
- **production build** — a build made with `ipe release`, intended to ship.
  It holds the program to stricter rules than a development build.
- **`ipe release`** — the command that requests a production build. Use
  `ipe dev build` or `ipe dev run` during development.
