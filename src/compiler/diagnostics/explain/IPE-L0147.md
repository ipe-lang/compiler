# IPE-L0147: `CustomElement.node` is browser-only and cannot be used outside a Web/WebView shape

A `CustomElement` handle names a JavaScript module that defines a browser custom
element (a `<my-editor>`-style tag). `CustomElement.fromFile` makes the handle,
and `CustomElement.node` mounts it in a view. Only a browser page can run that
module, and only a `Web.tea` program serves one.

Constructing the handle is enough to be refused. Its JS ships with the program
whether or not a view mounts it, and the `web` runtime module that serves the JS
is linked only into a Web build. A script (`main : Task ()`), a terminal app
(`Tui.tea`, `Cli.tea`) or a worker (`Worker.tea`) links no such module, so the
compiler refuses the constructor at its own line instead of emitting Rust that
would fail to build.

```ipe ipe:error
-- rejected: a browser custom element constructed in a Script (`Task ()` main)
import Ipe.Ffi.Js.CustomElement as CustomElement exposing (CustomElement)
import Ipe.Io as Io

editor : CustomElement String String
editor =
    CustomElement.fromFile "src/js/editor.js"

main : Task ()
main =
    Io.println "hi"
```

The refusal follows the handle into every module the program links. A
constructor in a helper module is refused the same way, even when nothing
uses the name that holds it.

## How to fix

**Construct and mount the widget in a `Web.tea` program.** A Web build serves the
widget's JS and decodes the events it sends back into your messages:

```ipe ipe:skip a fragment; the continuing view wiring is assumed from context
-- accepted: a custom element mounted in a `Web.tea` view
module Main exposing (main)

import Ipe.Tea.Web as Web
import Ipe.Ui exposing (Element)
import Ipe.Ffi.Js.CustomElement as CustomElement exposing (CustomElement)

editor : CustomElement String String
editor = CustomElement.fromFile "src/js/editor.js"

view : Model -> Element Msg
view model =
    CustomElement.node editor model.state FromWidget

main =
    Web.tea { init = init, update = update, view = view, subscriptions = subs }
```

**In a script, terminal app or worker, drop the handle.** Build the view from the
native `Ipe.Ui` elements every shape renders, such as `Ui.text`, `Ui.column` and
the `Ipe.Input` builders:

```ipe ipe:skip a fragment; Model and Msg are assumed from context
-- accepted in every shape: native Ipe.Ui instead of a browser widget
view : Model -> Element Msg
view model =
    Ui.column []
        [ Ui.text "editor:"
        , Ui.text model.state
        ]
```

## Why this happens

The compiler reads the program's shape from its `main` (`Web.tea`, `Tui.tea`,
`Cli.tea`, `Worker.tea`, or a plain `Task`) and judges every
`CustomElement.fromFile` the program links, reached or not, because the build
ships each one. A shape that serves no browser page fails closed at the first
constructor, so a browser widget outside the browser is a typed refusal at
`ipe` time, never a dead element or a `cargo build` failure after `ipe` reported
success.
