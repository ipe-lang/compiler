# IPE-T0023: this type is too large

A type is built from parts: a pair `( a, b )` is one part plus the parts of
`a` and `b`. This error means the type of a value is built from more parts than
I allow — 65,536 — once every repeated piece is counted where it appears.

The usual source is a value that holds the one before it twice. Each step
doubles the size of the type, so a short chain is already enormous:

```ipe ipe:skip an outline of a doubling chain; the real one is 16 steps
p0 = 0
p1 = ( p0, p0 )
p2 = ( p1, p1 )
-- … and so on, each pairing the last with itself …
p16 = ( p15, p15 )
```

`p16` is only sixteen definitions long, but its type has 2^17 − 1 parts. The
message names the limit and never prints the type, because printing it would
write out every one of those parts.

## Why the limit exists

The checker, the code generator and the Rust compiler each walk the whole
type, part by part. Without a ceiling, a few lines of source could make them
use memory and time without end. Stopping with a clear error at the place that
crossed the line keeps the compiler fast and its memory bounded.

## Right

Name the repeated part with its own type, so the type stays small however the
value grows:

```ipe
type Tree
    = Leaf Int
    | Node Tree Tree

tree : Tree
tree =
    Node (Leaf 0) (Leaf 1)
```

When the data really is a long sequence, keep it in a list:

```ipe
pairs : List ( Int, Int )
pairs =
    [ ( 0, 0 ), ( 1, 1 ) ]
```
