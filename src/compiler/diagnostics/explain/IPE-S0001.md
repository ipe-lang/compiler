# IPE-S0001: unsafe escape hatch imported without acknowledgment

Your program imports an `Ipe.<Module>.Unsafe` module — a disclosed *escape
hatch*. Every such module holds a member that mints a security-tier value by
*assertion* instead of by *parse*: it skips the check the safe path runs. That
is a real exposure (an XSS sink, a raw-SQL sink, a secret leak), so I ask you to
take responsibility for it before I build or run.

This is not a nag on ordinary code. The safe path is silent. The warning fires
*only* when your own code reaches for a disclosed `.Unsafe` import — the one act
that opens the hatch.

## The safe path is untouched

Code that never imports a `.Unsafe` module gets no warning, no prompt, no flag:

```ipe
import Ipe.Html exposing (text, section)

view summary =
    section [] [ text summary ]  -- escaped, safe: nothing to acknowledge
```

## What triggers the acknowledgment

Importing a disclosed escape hatch is the trigger. Here the raw sink bypasses
the XSS escaper:

```ipe
import Ipe.Html.Unsafe exposing (unsafeRaw)

view trusted =
    unsafeRaw trusted  -- verbatim HTML, no escaping: a real XSS sink
```

## How to acknowledge

- **Interactively** (a real terminal): I print the risk and prompt; answer `y`
  to proceed, `n` to stop.
- **In CI / non-interactively** (no terminal): I never block on a prompt — a
  build that hangs waiting for stdin is worse than the risk it guards. Without
  pre-acceptance the build fails closed with this code. Pre-accept in one of two
  ways:
  - the one-off flag: `ipe dev build --accept-risks` / `ipe dev run --accept-risks`;
  - the durable, reviewable manifest token in `package.ipe`:

```ipe ipe:skip
-- package.ipe
-- package =
--     { name = "my-app"
--     , capabilities = { accepts = [ Unsafe ] }
--     }
```

With either, the build proceeds silently and CI stays quiet.

## Reimposing a hard ban

The acknowledgment is consent, not enforcement of a resource axis — `unsafe` is
a provenance disclosure, like `native-ffi`. A deployment that forbids the escape
hatch entirely gets that stance by declaring no `unsafe` acceptance and letting
this fail-closed path reject any `.Unsafe` import.

## Glossary

- **escape hatch** — a function that deliberately skips a safety parse. In Ipê
  every one lives in a disclosed `Ipe.<M>.Unsafe` module and is named `unsafe*`.
- **capability** — one axis of what a program may touch or assert; `unsafe` is
  the axis that a value was minted by assertion, not by proof. From Latin
  *capax*, "able to hold".
- **fail closed** — when consent is absent and cannot be asked for, refuse
  rather than proceed. The safe default is to stop.
