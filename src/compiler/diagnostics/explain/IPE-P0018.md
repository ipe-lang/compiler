# IPE-P0018: a space before '.' reads as an accessor function

I found a `.` with a space before it, right after an expression:

```ipe ipe:skip illustrates the space-before-dot shape, person is a placeholder
name =
    person .name
```

That space changes what the `.` means. With no space, `person.name` reads
as one thing: the field `name` taken out of the record `person`. With a
space, `person .name` reads as two things side by side — the value
`person`, and then `.name` on its own. A lone `.name` is an *accessor
function*: it takes any record that has a `name` field and returns that
field, so `.name` behaves like `\r -> r.name`.

Ipe cannot type an accessor function yet — describing "any record that has
a `name` field" needs a feature (row polymorphism) that is still being
built — so rather than guess which reading you meant, I stop here.

If you meant field access, close the gap so the two names read as one path:

```ipe ipe:skip illustrates the closed-gap field access shape, person is a placeholder
name =
    person.name
```

The same fix applies wherever the space slipped in, including after a
parenthesised expression:

```ipe ipe:skip illustrates the space-before-dot shape after a parenthesised expression, wrap is a placeholder
value =
    (wrap 41) .value    -- space: reads as the accessor .value
```

```ipe ipe:skip illustrates the closed-gap shape after a parenthesised expression, wrap is a placeholder
value =
    (wrap 41).value     -- no space: field access on the result
```
