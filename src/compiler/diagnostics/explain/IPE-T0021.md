# IPE-T0021: this `any` is tied to another type, so it cannot stay a wildcard

A wildcard **`any`** in a signature says "I don't care what type goes here".
Every call of the function gets its own, independent type for each `any`, and
the compiled function takes each `any` as its own separate generic type. That
promise only holds while the body treats the `any` as an unrelated value, or
settles it to one exact type like `Int` or `List String`.

This error means the body ties the `any` to something else:

* to one of the signature's **type variables** (`a`),
* to the `any` of **another parameter**, or
* to a type that is only **partly known** (`List a`, `Maybe a`, a record with
  extra fields left open).

Each call site would then pick the `any` on its own while the body needs it to
match that other type, so no single compiled function fits every call.

## Wrong

The body puts `y` in the same list as `x`, so `y` must be the type `a`:

```ipe ipe:error
pair : a -> any -> List a
pair x y =
    [ x, y ]
```

The body compares the two parameters, so both `any`s must be the same type:

```ipe ipe:error
same : any -> any -> Bool
same x y =
    x == y
```

The body only works on lists, but leaves the element type open:

```ipe ipe:error
import Ipe.List as List

count : any -> Int
count xs =
    List.length xs
```

## Right

Name the shared type with a type variable, so every call agrees on it:

```ipe
import Ipe.List as List

pair : a -> a -> List a
pair x y =
    [ x, y ]

same : a -> a -> Bool
same x y =
    x == y

count : List a -> Int
count xs =
    List.length xs
```

Or write the exact type the body needs (`String -> String -> Bool`). An `any`
the body settles to one exact type (`any -> Int` with `x + 1`) or never looks
into (`any -> String` returning a constant) stays accepted.

## Why the restriction exists

The compiler turns every `any` into its own generic parameter of the generated
Rust function. If the body quietly required two of them to be equal, or one to
match a type variable, the generated Rust would not compile — the
"type-checks in Ipê, fails in `cargo`" class this compiler treats as a hard
bug. Rejecting the signature here, at type-check time, keeps every accepted
program buildable.
