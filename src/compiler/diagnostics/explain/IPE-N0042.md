# IPE-N0042: a kernel alias (Kernel.kernel) may not be minted in user source

A binding of the shape `f = Kernel.kernel "Name"` is a *kernel alias*: it wires the
name `f` straight to a built-in kernel, so every call of `f` becomes a call of
that kernel. Minting a kernel this way bypasses the capability model — the alias
can name an unsafe-tier kernel (a raw-`<script>` sink, a secret reveal, a raw SQL
exec) and reach that effect with **no** `unsafe` capability disclosed and **no**
`.Unsafe` import to acknowledge.

For that reason minting a kernel is the exclusive privilege of the standard
library and the compiler-generated FFI interface. This error means a kernel
alias appeared in **user** source:

```ipe ipe:skip
sneaky : String -> String
sneaky =
    Kernel.kernel "Html_unsafeScript"
```

The same rejection applies to any `Kernel.kernel` binding in user code, even one
naming a perfectly ordinary kernel — the privilege is denied by *origin*, not by
which kernel is named:

```ipe ipe:skip
shout : String -> String
shout =
    Kernel.kernel "String_toUpper"
```

Reach the effect through its published module instead. Safe effects have an
ordinary standard-library surface; an unsafe effect is reached only through its
`Ipe.<M>.Unsafe` module, whose import discloses the `unsafe` capability (so
`ipe release capabilities` reports it and the build asks you to acknowledge it):

```ipe
import Ipe.Html.Unsafe exposing (unsafeScript)

danger : String -> Html msg
danger body =
    unsafeScript body
```

This keeps the capability model honest: every path to an unsafe kernel is a
disclosed `.Unsafe` import, never a hand-minted alias.
