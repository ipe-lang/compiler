# IPE-P0074: a qualified constructor in pattern position

A constructor built in an expression may carry its module qualifier
(`Module.Ctor`), but a `case` pattern never does — patterns match a
constructor by its bare name only. Writing the qualifier where a pattern
expects a bare name is refused here rather than read as some other kind of
token.

For example, matching through an import alias:

```ipe ipe:error
describe : Int -> Int
describe code =
    case code of
        Error.InvalidInput -> 400
        _ -> 500
```

The same rule reaches every pattern position, not only the outermost one — a
qualifier nested inside a list or tuple pattern is refused the same way:

```ipe ipe:error
firstStatus : List Int -> Int
firstStatus codes =
    case codes of
        [ Status.Ready ] -> 1
        _ -> 0
```

Bring the type's constructors into unqualified scope with
`import Module exposing (Type(..))`, then match the bare name:

```ipe
type Status
    = Ready
    | Missing

describe : Status -> String
describe status =
    case status of
        Ready -> "ready"
        Missing -> "missing"
```
