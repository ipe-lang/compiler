# IPE-P0023: a mobile bundle needs the wasm client

You asked for a mobile bundle with `web solo <ios|android>`, and the project's
`[wasm]` mode is off or absent. A mobile bundle hosts the app's browser client
in the system webview of an iOS or Android shell, and that client is the wasm
build. With no wasm target there is no hostable browser bundle, so I stop
before laying out a shell around nothing.

## The safe path is untouched

A project that keeps `wasm` off still builds as a native or served app; only
the mobile bundle needs the browser client:

```ipe
import Ipe.Html exposing (text, section)

view summary =
    section [] [ text summary ]
```

## What triggers the refusal

The command names a mobile host while the `wasm` field of `package.ipe` is off
or missing:

```ipe ipe:skip a shell command, shown for its shape
ipe dev build web solo android
-- error: the project's wasm mode is off
```

## How to fix it

Turn the wasm client on in `package.ipe`, in `Solo` mode (or `Hydrate`), so a
browser bundle exists to host:

```ipe ipe:skip a manifest fragment, shown for its shape
-- package.ipe
-- package =
--     { name = "my-app"
--     , wasm = On { mode = Solo }
--     }
```

## Glossary

- **wasm client** — the browser build of the app, compiled to WebAssembly.
- **mobile bundle** — the iOS or Android shell project that hosts the browser
  client in a system webview.
- **fail closed** — when no browser client exists to host, refuse rather
  than write a shell that shows nothing.
