# IPE-N0038: an asserted foreign call (Rust.Ffi.call) is malformed

You used `Rust.Ffi.call` — the low-ceremony escape hatch for calling one
Rust function directly — but the use site does not have the one shape I
can check. I stopped before generating any foreign code.

## The one accepted shape

An asserted call is a *complete, annotated, top-level definition* whose
body is exactly `Rust.Ffi.call` applied to one string literal:

```ipe ipe:skip needs a real Rust crate registered via `ipe rust add` and present in the installed-crate catalog; the checker's scratch project has no Cargo.toml and no catalog entry, so even this well-shaped call is refused with IPE-F4414, never accepted
import Rust.Ffi

frobnicate : Int -> Result Error Int
frobnicate =
    Rust.Ffi.call "some_crate::frobnicate"
```

Three parts, all required:

1. **The annotation** (`frobnicate : Int -> Result Error Int`). This is
   your *assertion* — the signature you vouch the Rust function has. I
   have no inspected signature to fall back on here, so the annotation
   is not optional documentation; it is the contract the generated shim
   is built from. The result must be `Result Error <T>`: that `Err`
   channel is where a foreign failure — including a panic inside the
   crate — lands as a typed value.
2. **The string literal** (`"some_crate::frobnicate"`). The full Rust
   path to the function, as you would write it in Rust. It must be a
   literal — never a computed string — because I parse and validate it
   at compile time, and a runtime string could smuggle arbitrary text
   into generated Rust source.
3. **The whole body, with no parameters on the left.** The definition
   takes no arguments itself; the annotation carries the arrow type,
   and callers apply the value as an ordinary function.

## Shapes I refuse

The definition must not take parameters — the arrow lives in the
annotation, so this is refused:

```ipe ipe:error
import Rust.Ffi

frobnicate : Int -> Result Error Int
frobnicate x =
    Rust.Ffi.call "some_crate::frobnicate" x
```

And the call must not be buried inside a larger expression — this is
refused too, because there is no annotation attached to the site to
serve as the assertion:

```ipe ipe:error
import Rust.Ffi
import Ipe.Io as Io
import Ipe.String as String

main : Task Error ()
main =
    case (Rust.Ffi.call "some_crate::frobnicate") 3 of
        Ok n -> Io.println (String.fromInt n)
        Err _ -> Io.println "failed"
```

Other refusals in this class: a definition with no type annotation, a
non-literal path (a variable, a concatenation, an `if`), a bare
`Rust.Ffi.call` passed around as a value, and a path that is not a
plain `crate::path::function` — empty segments, illegal characters, or
generics are all rejected.

## Why so strict

`Rust.Ffi.call` skips *ceremony*, never *soundness*. Everything that
crosses the FFI boundary is typed, and the escape hatch keeps that
invariant only because the whole construct is decided at compile time:
a validated path, an author-asserted signature, and a compiler-owned
shim. Any shape I cannot fully resolve at compile time would turn the
escape hatch into a string-to-native-code channel, so it is refused.

If the function you want is already bound by `ipe rust add`, prefer the
inspected import — zero ceremony at the call site and a
compiler-checked signature:

```ipe ipe:skip illustrates the `ipe rust add`-bound import alternative, which needs an actual bound crate module present in the project; the checker's scratch project never has one installed
import Rust.SomeCrate as SomeCrate

answer : Result Error Int
answer =
    SomeCrate.frobnicate 21
```
