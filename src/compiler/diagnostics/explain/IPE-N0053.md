# IPE-N0053: a type alias row argument cannot extend its record

A `type alias` whose body is an open record names its row as a parameter:

```ipe
type alias Named r =
    { r | name : String }
```

Applying the alias fills that row. A record argument adds its fields to the
alias's own, so `Named { age : Int }` is exactly `{ age : Int, name : String }`,
and a type variable keeps the record open, so `Named a` is `{ a | name : String }`:

```ipe
type alias Named r =
    { r | name : String }

describe : Named { age : Int } -> String
describe person =
    if person.age > 17 then person.name else "minor"
```

The argument is refused when it cannot extend the record. A type that is not a
record or a type variable has no fields to add:

```ipe ipe:error
type alias Named r =
    { r | name : String }

-- rejected: `Int` is not a record
label : Named Int -> String
label person =
    person.name
```

An argument that repeats one of the alias's own labels would give the record
that label twice:

```ipe ipe:error
type alias Named r =
    { r | name : String }

-- rejected: `Named` already has a `name` field
label : Named { name : Int } -> String
label person =
    person.name
```

## How to fix

Pass a record holding only the extra fields, or a type variable when the
function accepts any record that has the alias's fields:

```ipe
type alias Named r =
    { r | name : String }

greet : Named a -> String
greet person =
    "hello " ++ person.name
```

## Why this is an error

An alias is expanded in place. When the argument cannot be spliced into the
row, there is no record type the annotation could stand for, so accepting it
would give the function a type that ignores what you wrote.
