# IPE-P0071: a carriage return must be followed by a newline

The file holds a carriage return (`\r`, byte `0x0D`) that is not directly
followed by a newline (`\n`). Editors, language servers and most viewers start
a new line at such a byte; the compiler does not, so the same file would have
two line structures. Code you see on its own line could be, to the compiler,
the tail of the `--` comment above it, and an editor's line numbers would point
at the wrong text. Rather than pick one reading, the compiler refuses the byte.

A `\r\n` pair (Windows line endings) is one line break and is accepted.

The byte is invisible in most editors, so this page writes it as `␍`. The line
below reads as a comment and a check to a viewer that breaks at `␍`; the
compiler would read it as one comment:

```ipe ipe:skip a lone carriage return cannot be written in a Markdown page
module Gate exposing (allowed)

allowed : Bool -> Bool
allowed authorized =
    -- note␍if authorized then True else False
    False
```

## To fix

Replace each lone `\r` with a line break, or delete it, then save the file with
one kind of line ending: `LF`, or `CRLF` where every `\r` is followed by `\n`
(most editors offer a "line endings" setting). The line above then holds the
code it showed:

```ipe
module Gate exposing (allowed)

allowed : Bool -> Bool
allowed authorized =
    -- note
    if authorized then True else False
```

If the `\r` was meant to stay inside a string, write it as the escape `\r`:

```ipe
module Gate exposing (reset)

reset : String
reset =
    "\r"
```
