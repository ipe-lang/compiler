# IPE-P0013: integer literal out of range

I read an integer literal that does not fit in Ipe's `Int`. The digits
are all valid, but the value they spell lies outside the range Ipe can
hold, so I can't turn it into a real number.

`Int` in Ipe is a 64-bit signed integer: every whole number from
`-9223372036854775808` to `9223372036854775807` has a literal, and
nothing outside that range does. Silently wrapping an out-of-range
literal around to a wrong value would be worse than stopping — so I
stop here. The fix is to use a value that fits, or to reach for a type
built for larger or fractional numbers.

A literal past either end lands here:

```ipe ipe:error
huge =
    999999999999999999999999999999
```

```ipe ipe:error
tooSmall =
    -9223372036854775809
```

Both ends themselves are fine:

```ipe
smallest =
    -9223372036854775808


largest =
    9223372036854775807
```

The magnitude `9223372036854775808` is an `Int` only under a unary
minus written right against it; on its own, after a binary `-`
(`a - 9223372036854775808`), or as `-(9223372036854775808)`, it is out
of range.

If the magnitude isn't essential, use a value within range:

```ipe
big =
    1000000000
```

If you really need arbitrary-size or fractional magnitudes, model the
quantity with a wider numeric type rather than a bare `Int` literal:

```ipe
price : Float
price =
    9.99
```
