# IPE-N0012: type defined more than once

You declared two types with the same name in this module. A type name has to be unique, because every annotation that mentions the name has to resolve to exactly one declaration. I point at both so you can see which two collide.

To fix this, rename one of the types, or — if the two were meant to be the same type — merge them into a single declaration.

Here `Color` is declared twice:

```ipe ipe:error
type Color
    = Red
    | Green

type Color
    = Light
    | Dark
```

Rename one so each type has its own name:

```ipe
type Color
    = Red
    | Green

type Shade
    = Light
    | Dark
```

If they describe the same idea, keep one declaration that lists every variant:

```ipe
type Color
    = Red
    | Green
    | Light
    | Dark
```

The same code fires when a local type's name collides with one brought in by an EXPLICIT import (`exposing (Name)` or `exposing (Name(..))`) — that clash is refused right here, at the declaration, exactly like two local duplicates. A name shared only with an OPEN import (`exposing (..)`) is different: it defers to the first bare use instead (see IPE-N0024).
