# IPE-T0003: type inference exceeded its step budget

Working out the types in your program took more steps than I allow
myself for a single run, so I stopped. This isn't a mistake in your
code as such — I simply ran into a deliberate ceiling I keep on how
much work type inference may do before it gives up.

This bound is on purpose, not a flaw. Without a cap, a pathological or
machine-generated file could drive type-checking to consume memory and
time without end and take the whole compiler down with it. Stopping
cleanly and telling you about it is far better than hanging or
crashing. In ordinary hand-written code you'll essentially never reach
it; hitting it usually means an unusually large generated module, or a
tangle of definitions that forces type-checking to do far more work
than expected.

Two separate stages carry this ceiling. Constraint solving (working
out the types themselves) is bounded by `IPE_SOLVER_BUDGET`. Checking a
`case` for missing or redundant branches is bounded by
`IPE_EXHAUST_BUDGET`; a match with many independent or-patterns
(`Red | Green`, `On | Off`, …) can otherwise expand combinatorially. If
you genuinely need a bigger budget, raise the matching variable to a
larger number. `IPE_SOLVER_BUDGET` is always a positive step count: `0`
is refused with this error. `IPE_EXHAUST_BUDGET` also accepts `0` to
disable its limit:

```ipe
-- A very large generated module can legitimately need more budget.
-- Build it with, for example:
--   IPE_SOLVER_BUDGET=20000000 ipec build Main.ipe
-- or, for a wide generated `case`:
--   IPE_EXHAUST_BUDGET=20000000 ipec build Main.ipe
big : Int
big =
    1 + 2 + 3
```

Often, though, the better fix is to give the solver less to chew on at
once. Splitting one enormous chain of inference into smaller, named
pieces with `let` shrinks the work dramatically:

```ipe ipe:skip an outline over helper functions defined elsewhere
total : Int
total =
    let
        a = step1 input
        b = step2 a
        c = step3 b
    in
    c
```

Adding explicit type annotations also helps — every annotation pins a
type down so I don't have to infer it, which cuts the number of steps:

```ipe ipe:skip an outline over a helper function defined elsewhere
parsed : Int
parsed =
    fromText rawInput
```

Don't simply keep raising the budget to mask a runaway definition;
restructure the code first, and lift the limit only when the size is
real and intentional.
