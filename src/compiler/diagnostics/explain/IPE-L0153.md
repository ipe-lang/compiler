# IPE-L0153: Ui.cells is terminal-screen-only and not available in the Cli shape

`Ui.cells` paints a **raw character grid** onto the terminal. It is a
full-screen terminal primitive — it writes cell-by-cell into the alternate
screen that `Tui.tea` renders.

A **Cli** app (`Cli.tea`) works differently: its `view` returns a
`Lines msg` — a line-oriented stack of styled text lines, from
`Ipe.Ui.Cli`. There is no alternate screen, no cell grid, and no
character-cell surface to paint on, so `Ui.cells` has no denotation there.

A `Lines msg` view cannot even reach for `Ui.cells` directly — putting an
`Element msg` where a `Lines msg` is required is an ordinary type mismatch
(IPE-T0001), caught before lowering. What this diagnostic catches is the
same `Ui.cells` call reached a different way: through a helper that type-checks
fine on its own (its signature says `Element msg`) but is still *reachable*
from a `Cli.tea` entry — shared render code pulled into a build where it has
no denotation:

```ipe ipe:error
module Main exposing (main)

import Ipe.Tea.Cli as Cli
import Ipe.Tea.Cli.Cmd as Cmd
import Ipe.Tea.Cli.Sub as Sub
import Ipe.Ui as Ui
import Ipe.Ui.Cli as CliUi
import Ipe.Ui.Cli exposing (Lines)

type Msg
    = NoOp

type alias Model =
    { count : Int }

-- rejected: `Ui.cells` only has a denotation in a Web/WebView build; this
-- helper type-checks on its own, but `Cli.tea` below makes it reachable
-- at the one point it is emitted
preview : Model -> Element Msg
preview model =
    Ui.cells [ [ 'h', 'i' ] ]

init : () -> ( Model, Cmd Msg )
init _unit =
    ( { count = 0 }, Cmd.none )

update : Msg -> Model -> ( Model, Cmd Msg )
update _msg model =
    let
        _preview = preview model
    in
    ( model, Cmd.none )

view : Model -> Lines Msg
view model =
    CliUi.text "ok"

subscriptions : Model -> Sub Msg
subscriptions _model =
    Sub.none

main =
    Cli.tea
        { init = init
        , update = update
        , view = view
        , subscriptions = subscriptions
        }
```

## How to fix

**If you want a full-screen cell-grid app**, switch to `Tui.tea`.
Its `view` returns a `Screen` tree and can contain `Cells.cells` islands:

```ipe
module Main exposing (main)

-- accepted: `Cells.cells` inside a `Tui.tea` view
import Ipe.Tea.Tui as Tui
import Ipe.Tea.Tui.Cmd as Cmd
import Ipe.Tea.Tui.Sub as Sub
import Ipe.Ui.Cells as Cells exposing (Screen)

type Msg
    = NoOp

type alias Model =
    { grid : List (List Char) }

init : () -> ( Model, Cmd Msg )
init _unit =
    ( { grid = [ [ 'h', 'i' ] ] }, Cmd.none )

update : Msg -> Model -> ( Model, Cmd Msg )
update _msg model =
    ( model, Cmd.none )

view : Model -> Screen Msg
view model =
    Cells.column []
        [ Cells.text "board:"
        , Cells.cells model.grid
        ]

subscriptions : Model -> Sub Msg
subscriptions _model =
    Sub.none

main =
    Tui.tea
        { init = init
        , update = update
        , view = view
        , subscriptions = subscriptions
        }
```

**If you want line output**, format the content as a `String` instead:

```ipe
import Ipe.List as List
import Ipe.String as String

type alias Model =
    { grid : List (List Char) }

view : Model -> String
view model =
    String.join "\n" (List.map String.fromList model.grid)
```

## Why this is an error

`Cli.tea` is the **Cli** shape — it is line-oriented I/O, not a
full-screen TUI. `Ui.cells` builds an `Element::Cells` node whose only
renderer is the terminal backend; the Web/Cli render path has no case for it
and would silently drop it to blank output. Rather than let a reachable
`Ui.cells` call compile clean and then render as nothing the first time a
Cli build actually runs it, the gate catches the call at the one point it is
emitted — naming it as an `ipe`-time diagnostic instead of a silent blank
screen discovered later.
