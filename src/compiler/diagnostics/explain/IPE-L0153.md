# IPE-L0153: Ui.cells is terminal-screen-only and not available in the Cli shape

`Ui.cells` paints a **raw character grid** onto the terminal. It is a
full-screen terminal primitive — it writes cell-by-cell into the alternate
screen that `Tui.tea` renders.

A **Cli** app (`Cli.tea`) works differently: its `view` returns a
`String` that is printed as a line on stdout. There is no alternate screen, no
cell grid, and no character-cell surface to paint on, so `Ui.cells` has no
denotation there.

```ipe ipe:error
-- rejected: `Ui.cells` under `Cli.tea` (no cell grid in a Cli view)
module Main exposing (main)

import Ipe.Tea.Cli as Cli
import Ipe.Ui as Ui

view : Model -> String
view model =
    Ui.cells [ [ 'h', 'i' ] ]   -- type error: returns Element, not String

main =
    Cli.tea
        { init = init, update = update, view = view
        , subscriptions = subs
        }
```

## How to fix

**If you want a full-screen cell-grid app**, switch to `Tui.tea`.
Its `view` returns a `Cells` tree and can contain `Cells.cells` islands:

```ipe
-- accepted: `Cells.cells` inside a `Tui.tea` view
module Main exposing (main)

import Ipe.Tea.Tui as Tui
import Ipe.Ui.Cells as Cells exposing (Cells)

view : Model -> Cells Msg
view model =
    Cells.column []
        [ Cells.text "board:"
        , Cells.cells model.grid
        ]

main =
    Tui.tea
        { init = init, update = update, view = view
        , subscriptions = subs
        }
```

**If you want line output**, format the content as a `String` instead:

```ipe
view : Model -> String
view model =
    String.join "\n" (List.map String.fromList model.grid)
```

## Why this is an error

`Cli.tea` is the **Cli** shape — it is line-oriented I/O, not a
full-screen TUI. Allowing `Ui.cells` there would silently produce Rust that
type-mismatches (`Element msg` where `String` is required) and fails `cargo
build` after `ipe dev build` already reported success. The gate converts that into a
clean compile-time diagnostic so you know exactly what to change.
