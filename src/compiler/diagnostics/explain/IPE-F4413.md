# IPE-F4413: no runtime jail can be established around the emitted app

You asked me to *run* a release build of an Ipê program (`ipe release
run`, or launching a release bundle), and I refused because I could not build a safety cage — a
*runtime jail* — around the program while it runs. Rather than let it
run with your full privileges, I stopped.

This is different from the jail I build when you `ipe add` a crate: that
one wraps the *compile*. This one wraps the *finished program as it
runs*, so an effect the program never declared cannot happen.

## Why a running program needs a jail

Ipê reads a program's capabilities off its code — the network, the
filesystem, the environment, and so on. A pure program has none:

```ipe
main : Task ()
main =
    Io.println "hello"
```

But a program can also carry *native* Rust code (a `Rust.` wrapper),
and native code can make any system call regardless of what it declared.
The only thing that keeps such a program honest at run time is the jail:
it turns the declared set into an *enforced* set. A program that declares
`network` is allowed to reach the network; one that does not is stopped
by the kernel, not by trusting the code to behave:

```ipe ipe:skip
main : Task ()
main =
    Http.get "http://example.com"
        |> Task.andThen (\_ -> Io.println "fetched")
```

If I cannot build that cage, I cannot make the promise — so I refuse
rather than run the program unconfined.

## What I looked for

On Linux the jail is `bwrap` (bubblewrap) for the namespaces, `prlimit`
for the resource caps, and a `seccomp` filter for the syscall denials.
If `bwrap` is missing, or `prlimit` is missing, or the kernel will not
install the `seccomp` filter, the cage cannot be built and you get this
refusal. On macOS and other platforms there is no jail yet, so a program
with a non-empty native capability set refuses to run there.

## What to do

- On Linux, install bubblewrap (`bwrap`, usually the `bubblewrap`
  package) and `prlimit` (usually `util-linux`).
- A pure program (no native capabilities) is unaffected — its guarantee
  is structural and needs no jail:

```ipe
-- runs anywhere, jailed or not, because it can touch nothing:
main : Task ()
main =
    Io.println (String.toUpper "safe")
```

- There is no override: no flag or variable runs admitted native code
  unconfined. `ipe dev run` checks no capabilities and runs no jail, so
  it never refuses with this code; the refusal comes from `ipe release
  run`, where the jail is the promise.

## Glossary

- **runtime jail / sandbox** — a restricted environment the finished
  program runs inside, so it can only do what it declared. "Jail" is the
  old BSD word; "sandbox" the modern one — same idea.
- **capability** — one axis of what a program may touch: the network,
  the filesystem, the environment, a subprocess. From Latin *capax*,
  "able to hold".
- **seccomp** — the Linux kernel feature that lets a process forbid
  itself from making chosen system calls. Short for *secure computing*.
- **namespace** — the kernel feature that gives a process its own
  private view of one resource (the network, process ids, mounts).
