# IPE-N0026: type name reserved for a built-in

A `type` or `type alias` declaration reuses a name that the compiler reserves for a built-in type (`Int`, `Float`, `Bool`, `String`, `Char`, `Bytes`, `Maybe`, `Result`, `List`, `Dict`, `Set`, `Task`, `Decoder`, `Cmd`, `Sub`, `Html`, `Element`, `Attribute`, `Length`, and the other framework types). These names are hard-wired into the compiler, so a user declaration that shadowed one would be silently ignored and the program would miscompile with no diagnostic. The name is rejected at declaration instead.

A user type that collides with a built-in:

```ipe ipe:error
module Main exposing (main)
import Ipe.Io as Io

type Length
    = Short
    | Long

main : Task Error ()
main = Io.println "hi"
```

This is rejected because `Length` is a built-in `Ipe.Ui` type. Rename your type so it no longer shadows the built-in:

```ipe
module Main exposing (main)
import Ipe.Io as Io

type Span
    = Short
    | Long

main : Task Error ()
main = Io.println "hi"
```

The same rule applies to `type alias` declarations — an alias may not reuse a built-in name either:

```ipe ipe:error
module Main exposing (main)
import Ipe.Io as Io

type alias Html = String

main : Task Error ()
main = Io.println "hi"
```

Only the type/alias *name* is checked. You may still freely use a reserved word as a *constructor* name (`type Palette = Color | Grey`) or reference the built-in itself in annotations (`x : Length`); only re-declaring the type name is rejected.
