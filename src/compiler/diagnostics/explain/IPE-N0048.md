# IPE-N0048: two definitions fold to one generated Rust name

Ipê compiles to Rust, and each of your definitions gets a generated Rust name. That name is built by mangling the definition's module path and its own name into a single identifier. The mangling folds away some distinctions — it lower-cases, it flattens the module boundary into the name — so two definitions that look different in Ipê can end up with the *same* Rust name.

When that happens, emitting two Rust items under one identifier would be a broken crate (the Rust compiler would reject it). Most of the time the compiler repairs this for you, silently giving the second definition a free name so the crate still emits. The one fold it cannot safely repair on its own — two field names that mangle to the same generated name — stops here instead: this is not a genuine redefinition, your two definitions really are different, so I do not guess which one to keep. I name both, show the shared generated name, and ask you to rename one.

A definition's own *name* can fold this way too — a module boundary that
flattens away leaves a bare top-level value and a nested one (`Border.rounded`
and a bare `borderRounded`) mangling to the same identifier. That collision is
not fatal on its own: the compiler disambiguates the second definition with a
free numeric suffix, so the program still emits and this diagnostic is never
raised for it. IPE-N0048 is reserved for the one fold a numeric suffix cannot
safely repair — a camel-case name and a snake-case name that fold together.
These are two different field names in Ipê, but both mangle to the same
synthesised witness trait, used by any function that reads the field off a
row-polymorphic record:

```ipe ipe:error
type alias Person a =
    { a | firstName : String, first_name : String }


describe : Person a -> String
describe person =
    person.firstName ++ person.first_name
```

Renaming the trait instead of asking would silently keep one field and drop
the other — the two names were written as two different fields on purpose, so
guessing which one you meant would change your program's meaning. Fail-closed
and name both.

To fix this, rename one of the two colliding fields so they no longer share a
generated witness-trait name:

```ipe
type alias Person a =
    { a | firstName : String, familyName : String }


describe : Person a -> String
describe person =
    person.firstName ++ person.familyName
```
