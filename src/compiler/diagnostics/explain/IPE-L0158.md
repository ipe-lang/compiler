# IPE-L0158: a route can never match because an earlier route matches first

Routes are tried in order and the first match wins. A route is unreachable
when an earlier route matches every path it matches: either the earlier
pattern is equivalent to it (see IPE-L0157), or, segment by segment, the
earlier route has the same literal, a `String` parameter, which matches any
segment, or a parameter whose type reads the later literal (`7` for an `Int`,
`true` for a `Bool`).

```ipe ipe:error
-- ✘ `/apps/:slug` (a `String`) already matches `/apps/new`.
routes = [ route "/apps/:slug" AppPage, route "/apps/new" NewAppPage ]

-- ✔ List the more specific route first.
routes = [ route "/apps/new" NewAppPage, route "/apps/:slug" AppPage ]
```

The same page listed twice under one pattern is also dead:

```ipe ipe:error
-- ✘ The second `/about` never matches.
routes = [ route "/about" AboutPage, route "/about" AboutPage ]
```

An `Int` parameter shadows a literal it reads, so `/posts/:id` before
`/posts/7` is refused. It does not shadow a literal like `latest`, which does
not parse as an `Int`:

```ipe ipe:skip a fragment; PostPage and LatestPage are assumed from context
-- ✔ `/posts/latest` is still reachable.
routes = [ route "/posts/:id" PostPage, route "/posts/latest" LatestPage ]
```
