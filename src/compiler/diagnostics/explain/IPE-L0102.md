# IPE-L0102: polymorphic value's type could not be determined

Ipe *can* compile a polymorphic function — a definition whose type
signature uses a type variable structurally (a pure pass-through like
`identity : a -> a`) lowers to a generic function. What it cannot yet do
is compile a *value* whose concrete type is never pinned down: when you
bind a polymorphic function to a name without ever using it at a specific
type, the compiler has nothing to monomorphise it into.

This is the value-position counterpart of generic-function support: the
function is fine, but a fully-polymorphic *value* needs a concrete type
the compiler can emit, and here none was determined.

`[feature: polymorphism]`

A polymorphic function on its own compiles — this is supported:

```ipe
identity : a -> a
identity x =
    x
```

The limit appears when you bind that function to a value but never apply
it at a concrete type, so its type stays `a -> a` with nothing to pin
`a`:

```ipe ipe:skip
identity : a -> a
identity x =
    x

main =
    let f = identity in
    println (String.fromInt 0)
```

Use the value at a concrete type — applying it determines the
instantiation, and the binding compiles:

```ipe ipe:skip
identity : a -> a
identity x =
    x

main =
    let n = identity 41 in
    println (String.fromInt n)
```

This is a current limitation of the Ipe Rust compiler, not a problem
with your code. If under-determined polymorphic values matter to your
project, please tell us at
https://github.com/ipe-lang/compiler/issues.

## An untyped helper used under a generic sibling

A binding with no type annotation has one type, shared by every use in its
module. When an annotated, generic sibling uses it, the helper's type takes
on the sibling's type variable, but the helper is not generic over that
variable itself, so the two functions could not agree once compiled. The
helper `chip` below borrows `msg` from `row` and is refused at its name:

```ipe ipe:error
import Ipe.Html as Html exposing (Html)
import Ipe.List as List

chip s =
    Html.em [] [ Html.text s ]

row : List String -> Html msg
row xs =
    Html.span [] (List.map chip xs)

framed : Html msg -> Html msg
framed inner =
    Html.div [] [ inner, row [ "r" ] ]
```

Give the helper its own signature, generic over its own variable, and every
use instantiates it afresh:

```ipe
import Ipe.Html as Html exposing (Html)
import Ipe.List as List

chip : String -> Html msg
chip s =
    Html.em [] [ Html.text s ]

row : List String -> Html msg
row xs =
    Html.span [] (List.map chip xs)

framed : Html msg -> Html msg
framed inner =
    Html.div [] [ inner, row [ "r" ] ]
```

## A type variable used two ways, left open at a call

A type variable left open at a call reads by its position: `()` in a UI
message slot (`Html msg`), the project error in a `Result` error slot
(`Result e a`), and the JSON carrier anywhere else. A variable the callee
uses in two such kinds of position would need two Rust types, so a call
that leaves it open is refused at the callee's name. Below, `pair` uses `a`
both in `Html a` and in `List a`, and `main` never fixes it:

```ipe ipe:error
import Ipe.Io as Io
import Ipe.Html as Html exposing (Html)

pair : Int -> ( Html a, List a )
pair n =
    ( Html.text "p", [] )

main : Task ()
main =
    case pair 1 of
        ( h, _ ) ->
            Io.println (Html.htmlRender (Html.div [] [ h ]))
```

Give each use its own variable, so each is used one way only, or fix the
variable at the call with a concrete type:

```ipe
import Ipe.Io as Io
import Ipe.Html as Html exposing (Html)

pair : Int -> ( Html a, List Int )
pair n =
    ( Html.text "p", [] )

main : Task ()
main =
    case pair 1 of
        ( h, _ ) ->
            Io.println (Html.htmlRender (Html.div [] [ h ]))
```

A `Result` error slot reads an open variable as the project error, so a
variable used both there and as a value is refused the same way:

```ipe ipe:error
import Ipe.Io as Io

both : Int -> ( Result e Int, List e )
both n =
    ( Ok n, [] )

main : Task ()
main =
    case both 1 of
        ( Ok _, _ ) ->
            Io.println "ok"

        ( Err _, _ ) ->
            Io.println "err"
```
