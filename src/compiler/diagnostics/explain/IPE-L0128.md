# IPE-L0128: alias over a dispatch-needing nested pattern not supported yet

An `as`-alias in a **refutable match-arm position** is fully supported when
its inner pattern is *dispatch-free* — a variable / wildcard leaf, or any
nesting of tuple / record / alias over such leaves:

```ipe ipe:skip a fragment; `useAll` is assumed from context
-- supported: `(a, b)` needs no runtime check, so the compiler can bind
-- the whole payload once and re-derive `a`/`b` from a clone.
describe m =
    case m of
        Just ((a, b) as w) ->
            useAll a b w

        Nothing ->
            none
```

What is **not** supported yet is an alias whose inner pattern itself needs a
runtime *dispatch* — a check that can fail, deciding whether the arm matches
at all: a nested constructor, a literal, or a list/cons pattern anywhere
inside the alias:

```ipe ipe:skip a fragment; `got` and `none` are assumed from context
-- IPE-L0128: `Just x` needs its own discriminant check inside the alias.
describe w =
    case w of
        Wrap ((Just x) as inner) ->
            got inner

        Wrap Nothing ->
            none
```

## Why

In a by-value match arm, Rust's `name @ inner` binding moves the whole value
into `name` **and** moves `inner`'s bindings out of the same storage — a
partial-move conflict for any non-`Copy` payload. The compiler repairs the
dispatch-free shape by binding the whole value once and re-deriving the
inner bindings from a clone (the same strategy `let` destructures use). That
repair is only sound when the inner pattern cannot fail: reconstructing the
alias binder from parts requires that no data was discarded by a runtime
check. An inner pattern that *can* fail (`Just x`, a literal, a cons cell)
would need the whole arm matched by reference instead — a materially larger
redesign tracked separately.

String and list match arms are unaffected: those already match by reference
(`case s of "hi" -> …`, `case xs of (x :: rest) as w -> …; [] -> …`), where
the alias spelling is a borrow and sound for any inner shape. Note this is
*list-mode* only — a cons-alias arm is by-reference just when the match is
in list mode (some arm's head is a bare list/slice pattern, e.g. the `[]`
arm above). An `as`-alias over a cons pattern in a match with no such
sibling arm is by-value and, being dispatch-needing, is L0128-rejected.

## How to fix

Bind the whole value with a plain name and match the inner shape in a
nested `case`:

```ipe ipe:skip a fragment; `got` and `none` are assumed from context
describe w =
    case w of
        Wrap inner ->
            case inner of
                Just x ->
                    got inner

                Nothing ->
                    none
```
