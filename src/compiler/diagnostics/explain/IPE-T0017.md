# IPE-T0017: built-in type cannot be updated with record syntax

A few types look like records but are **built into the compiler**:
`PanicInfo`, `TypeInfo`, `ErrorInfo` (the payloads of `ErrorDetails`), and the
server `Request`. You can *read* their fields — `p.message`, `req.path` —
because the compiler knows exactly which fields each one has. But they are not
ordinary records you assembled yourself, so the record-update syntax
`{ value | field = … }` does not apply to them: there is no way to "rebuild"
a built-in value field-by-field.

Think of it like a printed receipt: you can read every line on it, but you
cannot take a pen, change one line, and call the result a new official
receipt — the till (the runtime) is the only thing that issues them.

## Wrong

```ipe ipe:error
describe : PanicInfo -> PanicInfo
describe p =
    { p | message = "something friendlier" }   -- error: PanicInfo is built-in
```

## Right

Read the fields you need and build your OWN value around them — a plain
record, a string, or a fresh `Error`:

```ipe
describe : PanicInfo -> String
describe p =
    "panic: " ++ p.message
```

If the goal is to attach richer context to an error, build a new `Error`
value through the sanctioned constructors instead of mutating the built-in
payload:

```ipe
import Ipe.Error as Error

handle : PanicInfo -> Error
handle p =
    Error.unexpected ("recovered from panic: " ++ p.message)
```

## Why the restriction exists

Record update produces a *structural* record value, but the built-in types
are *nominal*: the runtime represents them with dedicated structures the
emitted code shares with the standard library. An updated copy would be a
structurally-different value with nowhere sound to flow — accepting it would
compile to Rust that fails to build (the exact "compiles in Ipe, fails in
cargo" class this compiler treats as a hard bug). Field *reads* stay fully
supported.

## Glossary

* **nominal type** — a type identified by its *name*, not its shape. From
  Latin *nomen*, "name". The compiler ties `PanicInfo` to one specific
  runtime structure.
* **structural record** — a type identified by its *shape* (which fields it
  has). Two records with the same fields are the same type, whatever you
  call them.
* **record update** — the `{ base | field = value }` syntax that copies a
  record while replacing some fields. It needs a structural record base.
