# IPE-N0043: a config binding is declared but never threaded into an app entry

Ipê lets an app gather its cross-cutting wiring — how it binds its host, what it logs, its database URL, its CSRF and session policy, its secrets — into one top-level binding named `config`, a plain `List (Setting shape)`:

```ipe
module Main exposing (main)

import Ipe.Tea.Web as Web
import Ipe.Ui as Ui
import Ipe.Tea.Web.Cmd
import Ipe.String
import Ipe.Tea.Web.Sub
import Ipe.App as App
import Ipe.Host as Host
import Ipe.Db as Db


type Page
    = CounterPage


type Msg
    = Increment


type alias Model =
    { page : Page
    , count : Int
    }


config =
    [ Host.bind Host.loopback
    , Web.csrf Web.strict
    , Db.url (App.fromEnv "DATABASE_URL")
    ]


init : WebReq -> ( Model, Cmd Msg )
init _req =
    ( { page = CounterPage, count = 0 }, Cmd.none )


update : Msg -> Model -> ( Model, Cmd Msg )
update msg model =
    case msg of
        Increment ->
            ( { model | count = model.count + 1 }, Cmd.none )


view : Model -> Element Msg
view model =
    Ui.text (String.fromInt model.count)


subscriptions : Model -> Sub Msg
subscriptions _model =
    Sub.none


main =
    Web.tea
        { init = init
        , update = update
        , view = view
        , subscriptions = subscriptions
        , routes = [ Web.route "/" CounterPage ]
        , notFound = CounterPage
        }
```

When a module has both a `config` binding and a `Web.tea` entry, the compiler threads `config` into the entry for you — it behaves exactly as if you had written `Web.appWith config { … }`. That threading is the *only* thing that installs the settings.

So a `config` binding that is **never** passed to an app entry is inert: the runtime never reads it, and every setting it lists is silently dropped — a host bind that never takes effect, a CSRF posture that is never enforced, a secret that is never loaded. That silent drop is a security footgun, so it is rejected here, mirroring the discarded-`Task` lint (IPE-L0141): a value whose whole purpose is a runtime effect must reach the site that consumes it.

This trips the gate — a `config` binding with no Web app entry to thread it into:

```ipe ipe:error
module Main exposing (main)

import Ipe.Io as Io
import Ipe.App as App
import Ipe.Host as Host
import Ipe.Db as Db


config =
    [ Host.bind Host.loopback
    , Db.url (App.fromEnv "DATABASE_URL")
    ]


main : Task Error ()
main =
    Io.println "the config above is never installed"
```

To fix it, give the module a settings-less `Web` entry — `Web.tea` or `Web.appRouted` — and the compiler threads the sibling `config` binding into it automatically, rewriting the entry to `Web.appWith config { … }` under the hood. Writing `Web.appWith` yourself does NOT pick this up: an explicit `Web.appWith` is taken to carry its own settings already, so a sibling `config` binding beside it has nowhere to go and is rejected the same way.
