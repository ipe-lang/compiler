# IPE-L0117: Float is not a valid Set element or Dict key on the Rust backend

Ipe's `Float` is a `comparable` value, so the type checker accepts a
`Set Float` or a `Dict Float v` — the typing follows Elm, which also treats
`Float` as comparable. Ipe nonetheless rejects it here, at lowering, for two
compounding reasons:

1. **Correctness — a `Float` key is a silent footgun.** A `Set`/`Dict` lookup is
   exact-key equality, and IEEE floats break that: `0.1 + 0.2 ≠ 0.3`, so a lookup
   by any *computed* float silently misses an entry stored under the "same"
   value. The collection looks right and quietly returns nothing. Keying on a
   float is almost always a latent bug.
2. **Representation.** `Set a` is backed by `BTreeSet<a>` and `Dict k v` by
   `HashMap<k, v>`, and Rust's `f64` implements neither `Ord` (NaN has no place in
   a total order) nor `Hash`/`Eq` (NaN is not equal to itself), so
   `BTreeSet<f64>` / `HashMap<f64, _>` would not even compile.

This is a **deliberate, permanent divergence from Elm** — a chosen correctness
guard, not an unimplemented feature. A total-order wrapper (ordered floats with
NaN as a designated extreme) would fix reason 2 but not reason 1, so it is
deliberately not adopted: it would trade a compile error for a silent runtime
bug, weakening Correctness to buy Completeness — which Ipe's precedence order
forbids.

## Use a totally-ordered, hashable element / key

`Int`, `Char`, `String`, and `Bool` are all `Ord` and `Hash` in Rust, so they
make sound `Set` elements and `Dict` keys:

```ipe
import Ipe.Set as Set exposing (Set)

ids : Set Int
ids =
    Set.fromList [ 1, 2, 3 ]
```

```ipe
import Ipe.Dict as Dict exposing (Dict)

prices : Dict String Int
prices =
    Dict.insert "apple" 120 Dict.empty
```

## Carry the Float as a value, key on something else

When you need `Float` data in a keyed collection, key on a stable identifier and
store the `Float` in the value position:

```ipe
import Ipe.Dict as Dict exposing (Dict)

readings : Dict String Float
readings =
    Dict.insert "sensor-a" 21.5 Dict.empty
```

If you genuinely need set membership over floating-point data, quantise it to an
`Int` (for example, cents instead of a fractional currency amount, or a rounded
bucket index) before inserting.
