# IPE-L0146: a Store accessor query/spec builder was applied point-free

The accessor-typed `Store.*` query leaves (`Store.eq`, `Store.neq`, `Store.gt`,
`Store.like`, `Store.inList`, …) and column-spec builders (`Store.primaryKey`,
`Store.serial`, `Store.unique`, `Store.defaultNow`, …) read their column from a
**field accessor** — a bare `.field` like `.age`. The compiler reads that
accessor at compile time, checks the field against the row type, and derives the
validated column name. The whole call is rewritten inline before any code is
generated.

Because that rewrite happens only when the call is applied **directly** — with
its accessor and value in one place — these builders have no value you can pass
around on their own. Writing one point-free (passing it as a function value, or
supplying only some of its arguments) reaches this error.

```ipe ipe:skip
-- wrong: `Store.eq .age` is partially applied and handed to `List.map`
List.map (Store.eq .age) ages
```

## Apply it directly

Give the builder its accessor and value in the same place:

```ipe ipe:skip
Store.query store
    |> Store.where (Store.eq .age 18)
```

## When you need a function value

If you genuinely need a function — say to pass to `List.map` or `Result.map` —
wrap the builder in a lambda that supplies the accessor. The lambda is an
ordinary function value; each time it is called it applies the builder directly,
so the accessor-intercept still fires:

```ipe ipe:skip
-- right: the lambda supplies `.age`; the builder is applied directly inside it
List.map (\age -> Store.eq .age age) ages
```

The same holds for a spec builder mapped over a `Result`:

```ipe ipe:skip
-- wrong
Store.fromColumns "users" columns
    |> Result.map (Store.primaryKey .id)

-- right
Store.fromColumns "users" columns
    |> Result.map (\store -> Store.primaryKey .id store)
```

## A query operator outside `Store.select`

The projection operators `Store.literal`, `Store.upper`, `Store.lower`,
`Store.coalesce`, `Store.add`, `Store.sub`, and `Store.mul` have no runtime
function either. They describe a computed column of a query, and the compiler
rewrites them into SQL only when they appear **directly** inside a
`Store.select` projection body. Called anywhere else — even with every argument
supplied — they reach this error:

```ipe ipe:error
import Ipe.Db.Store as Store

-- wrong: `Store.add` is a query operator, not integer addition
bump : Int -> Int -> Int
bump a b =
    Store.add a b
```

Outside a query, write the plain expression instead:

```ipe
-- right
bump : Int -> Int -> Int
bump a b =
    a + b
```

Inside a query, place the operator directly in the projection body:

```ipe ipe:skip fragment of a query pipeline: needs a store and row type in scope
-- right: the operator is an element of the `Store.select` body
Store.select (\( item, _ ) -> Store.add item.price (Store.literal 1))
```

## Why this happens

The column of a typed query is a **checked, closed identifier** derived from the
`.field` accessor at compile time — never a caller-supplied string. That check
runs only where the accessor and the rest of the call sit together. A point-free
or partial application would carry the builder to a place where the accessor is
no longer visible for that check, so the compiler rejects it here rather than
emitting code that cannot be built. Wrapping the builder in a lambda keeps the
accessor and the call together, which is why it is accepted.

## Glossary

- **field accessor** — the bare `.field` form (e.g. `.age`), a one-argument
  function that reads a record field. A `Store.*` builder uses it to name the
  column at compile time.
- **point-free** — writing a function by passing another function around without
  naming its argument (e.g. `List.map (Store.eq .age)` rather than
  `List.map (\age -> Store.eq .age age)`).
- **partial application** — calling a function with fewer arguments than it
  takes, producing a function that expects the rest.
- **query leaf** — a single `Cond` predicate such as `Store.eq .age 18`; leaves
  combine into the `WHERE` clause of a typed query.
- **column-spec builder** — a function that adds a column constraint to a store,
  such as `Store.primaryKey`, `Store.serial`, or `Store.defaultNow`.
