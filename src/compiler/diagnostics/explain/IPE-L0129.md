# IPE-L0129: routed Web.tea not supported in a web client build yet

Your app's Model carries a `page` field and the `Web.tea` config has a
`routes` list — that is a *routed* app: the server matches each incoming URL
against `routes` and constructs the right Page value before `init` runs.

This is the shape that triggers the error in a `web client` build:

```ipe ipe:error
type alias Model = { page : Page, count : Int }

main =
    Web.tea
        { init = init, update = update, view = view
        , subscriptions = subscriptions
        , routes = [ route "/" HomePage, route "/about" AboutPage ]
        , notFound = HomePage
        }
```

Built as `web client`, the app runs entirely in the browser, and the
piece that matches URLs to Pages (the client-side router: route matching,
`:param` capture, history integration) is not built yet. Accepting the
program would emit a call into a router that does not exist, so the compiler
stops here instead.

What works today in a `web client` build is the single-page shape — a Model
without a `page` field and an empty `routes` list:

```ipe ipe:skip
type alias Model = { count : Int }

main =
    Web.tea
        { init = init, update = update, view = view
        , subscriptions = subscriptions
        , routes = [], notFound = HomePage
        }
```

If your pages are UI states rather than URLs, a plain union field with any
other name keeps working — only the URL-routed `page` convention is gated:

```ipe ipe:error
type alias Model = { screen : Screen, count : Int }

update msg model =
    case msg of
        ShowSettings ->
            ( { model | screen = SettingsScreen }, Cmd.none )
```

If you need URL-based pages in the browser today, compile the app natively
(the server router already supports it) and revisit the wasm build when the
client router lands.

## Glossary

- **routed app** — a `Web.tea` whose Model has a `page` field; URLs map to
  Page values via `routes`.
- **client-side router** — the browser half of that mapping: matching
  `location.pathname`, capturing `:param` segments, and reacting to
  Back/Forward.
