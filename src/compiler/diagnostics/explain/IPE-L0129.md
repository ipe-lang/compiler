# IPE-L0129: routed Web.tea in a web client build

Your app's Model carries a `page` field and the `Web.tea` config has a
`routes` list — that is a *routed* app: URLs map to Page values via
`routes`. A routed app compiles the same way whether the router runs on the
server (a native build) or in the browser (a `web client` build) — the
client-side router (route matching, `:param` capture, history integration)
is built, so `routes` and `notFound` need no special casing per target.

```ipe
module Main exposing (main)

import Ipe.Tea.Web as Web
import Ipe.Tea.Web.Cmd as Cmd
import Ipe.Tea.Web.Sub as Sub
import Ipe.Ui as Ui

type Page = Home | About

type alias Model = { page : Page, count : Int }

type Msg = NoOp

init : WebReq -> ( Model, Cmd.Cmd Msg )
init _req =
    ( { page = Home, count = 0 }, Cmd.none )

update : Msg -> Model -> ( Model, Cmd.Cmd Msg )
update _msg model =
    ( model, Cmd.none )

subscriptions : Model -> Sub.Sub Msg
subscriptions _model =
    Sub.none

view : Model -> Element Msg
view _model =
    Ui.text "hello"

main =
    Web.tea
        { init = init
        , update = update
        , view = view
        , subscriptions = subscriptions
        , routes = [ Web.route "/" Home, Web.route "/about" About ]
        , notFound = Home
        }
```

The single-page shape — a Model without a `page` field and an empty
`routes` list — keeps working unchanged too:

```ipe ipe:skip a fragment; init, update, view, and subscriptions are assumed from context
type alias Model = { count : Int }

main =
    Web.tea
        { init = init, update = update, view = view
        , subscriptions = subscriptions
        , routes = [], notFound = HomePage
        }
```

If your pages are UI states rather than URLs, a plain union field with any
other name works exactly the same way — only the `routes` list decides
whether the app is routed, not the field's name:

```ipe
module Main exposing (main)

import Ipe.Tea.Web as Web
import Ipe.Tea.Web.Cmd as Cmd
import Ipe.Tea.Web.Sub as Sub
import Ipe.Ui as Ui

type Pane = SettingsPane | HomePane

type alias Model = { pane : Pane, count : Int }

type Msg = ShowSettings

init : WebReq -> ( Model, Cmd.Cmd Msg )
init _req =
    ( { pane = HomePane, count = 0 }, Cmd.none )

update : Msg -> Model -> ( Model, Cmd.Cmd Msg )
update msg model =
    case msg of
        ShowSettings ->
            ( { model | pane = SettingsPane }, Cmd.none )

subscriptions : Model -> Sub.Sub Msg
subscriptions _model =
    Sub.none

view : Model -> Element Msg
view _model =
    Ui.text "hello"

main =
    Web.tea
        { init = init
        , update = update
        , view = view
        , subscriptions = subscriptions
        , routes = []
        , notFound = HomePane
        }
```

## Glossary

- **routed app** — a `Web.tea` whose Model has a `page` field; URLs map to
  Page values via `routes`.
- **client-side router** — the browser half of that mapping: matching
  `location.pathname`, capturing `:param` segments, and reacting to
  Back/Forward.

`[feature: wasm-routed-app]`

This diagnostic code is reserved by the diagnostics registry; a routed
`Web.tea` no longer refuses in either a native or a `web client` build. If
you hit a case that still refuses, please tell us at
https://github.com/ipe-lang/compiler/issues.
