# IPE-L0142: a return-position wildcard `any` cannot be determined

A wildcard `any` is not a type variable. It is a promise: *"there is exactly one
concrete type here, and the compiler can work out which."* Ipê keeps that promise
by picking a single concrete type for every `any` before it generates code — so
`any` never becomes an open, caller-chosen type the way a named variable like `a`
does.

For that promise to hold, each `any` has to be **determinable**. In a parameter
position it always is: the caller passes an argument, and its type fixes the
`any`. In the return type, it can be worked out in one of two ways — from the
**body** (the value you return is concrete), or from a **parameter** that also
uses the same `any` (so the argument the caller passes fixes the result too).

## What went wrong

This signature's return `any` is determinable by neither. No parameter carries
it, and the body does not pin it to a concrete type:

```ipe ipe:skip the unpinned-return shape IPE-L0142 flags; shown without running the checker
foo : Int -> List any
foo _ = []
```

`[]` is an empty list of *some* element type, and nothing in `foo` — neither a
parameter nor the body — says which. The result would be a value whose type only
its own caller could choose, yet the caller has nothing to choose it with. A
tuple of unpinned results has the same problem:

```ipe ipe:skip the unpinned-return shape IPE-L0142 flags; shown without running the checker
bar : Int -> ( List any, Maybe any )
bar _ =
    ( [], Nothing )
```

Because a wildcard `any` must resolve to one concrete type and this one cannot,
the program is rejected here rather than later.

## How to fix it

**Pin it from the body.** Return a concrete value, and the `any` is the type of
that value:

```ipe
import Ipe.List as List

firstThree : Int -> List Int
firstThree n =
    [ n, n + 1, n + 2 ]
```

**Make it genuinely polymorphic.** If you truly want the caller to choose the
element type — an empty list of anything — that is a named type variable, not a
wildcard. Use `a`:

```ipe
emptyOf : List a
emptyOf =
    []
```

A named variable is real polymorphism: the same function works at every type,
resolved independently at each use. A wildcard `any` is the opposite — one fixed
concrete type — so it only belongs where that type can actually be worked out.

## Glossary

- **wildcard `any`** — a placeholder for one concrete type the compiler must be
  able to determine. Unlike a named variable, it is not left open for callers to
  instantiate.
- **type variable** — a name like `a` that stands for *any* type, chosen freshly
  at each use site. This is ordinary polymorphism.
- **determinable** — able to be worked out from the surrounding facts. A return
  `any` is determinable when the body or a parameter fixes its type.
- **polymorphic** — working uniformly at many types. From Greek *poly-* ("many")
  and *morphē* ("form"): "of many forms".
