# IPE-L0134: an equality- or ordering-requiring collection operation over a function-carrying element is not sound (a function is not comparable)

A function value can now be **stored** in a `List` element or a `Dict` value: it
is carried on a shared, reference-counted `Arc<dyn Fn>` handle, which is
`Clone`, so a `List (Int -> Int)` or a `Dict String (Event -> Msg)` can be built
and forwarded freely, and mapped/folded/filtered by the frontier-closed `List`
family (`List.map`, `List.filter`, `List.foldl`, `List.foldr`, `List.concatMap`,
`List.filterMap`, `List.any`, `List.all`, `List.find`, `List.indexedMap`).

What a function value is **not** is comparable. An `Arc<dyn Fn>` implements
neither equality (`PartialEq`) nor ordering (`PartialOrd`/`Ord`) — there is no
meaningful, decidable "are these two functions equal / which is smaller"
operation. So a collection operation that compares or orders its element has no
sound representation over a function element, and is rejected here at lowering
rather than emitting Rust that would not compile.

The equality- and ordering-requiring collection kernels are rejected:

- `List.member` (needs `==` on the element)
- `List.unique` (needs `==` to deduplicate)
- `List.sort`, `List.maximum`, `List.minimum` (need an ordering on the element)

## Some higher-order operations are not function-aware yet

A second, separate set of operations is also rejected over a function-carrying
element: the higher-order kernels that pass the element into a mapper or
comparator closure whose parameter carrier is not yet aligned to the stored
`Arc<dyn Fn>`. These would emit Rust that mixes the `Arc` (storage) carrier with
the `Box` (direct) carrier, which `cargo` rejects. Today they are:

- `List.partition`, `List.map2`, `List.map3`, `List.map4`, `List.map5`,
  `List.sortBy`, `List.sortWith`
- `Dict.map`, `Dict.foldl`, `Dict.foldr`, `Dict.filter`, `Dict.partition`,
  `Dict.update`

For example, mapping a `Dict` whose values are functions is rejected:

```ipe ipe:error
import Ipe.Dict as Dict exposing (Dict)

handlers : Dict String (Int -> Int)
handlers =
    Dict.singleton "inc" (\n -> n + 1)

-- rejected: Dict.map passes the function value to a closure whose
-- parameter carrier is not function-aware yet
bumped : Dict String (Int -> Int)
bumped =
    Dict.map (\_ f -> f) handlers
```

If you need to apply a stored function, look it up with a move/clone kernel
(`Dict.get`) and call the projected value — the lookup never passes the function
into a mapper closure, so it stays sound:

```ipe ipe:skip a fragment; handlers is assumed from context
applyNamed : String -> Int -> Int
applyNamed name x =
    case Dict.get name handlers of
        Just f ->
            f x

        Nothing ->
            x
```

## Compare on a non-function key instead

If you need membership or ordering, key on a comparable value and keep the
function in the value position:

```ipe ipe:skip a fragment; Event and Msg are assumed from context
handlers : Dict String (Event -> Msg)
handlers =
    Dict.insert "click" onClick Dict.empty

hasClick : Bool
hasClick =
    Dict.member "click" handlers
```

`Dict.member` compares the **key** (`String`), which is comparable; the value is
a function, which is stored, not compared.

## Store a tag alongside the function

When you have a list of functions and need to find or dedupe them, pair each with
a comparable tag and operate on the tag:

```ipe
type Step
    = Step String (Int -> Int)

run : Step -> Int -> Int
run step n =
    case step of
        Step _ f ->
            f n
```

Sort, dedupe, or search on the `String` tag; apply the function by projecting it
out of the pair.
