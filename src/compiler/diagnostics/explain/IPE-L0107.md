# IPE-L0107: function value in a record field not supported here

You put a function value into a record field — a lambda, or a function named or
returned as a value — in a position the compiler could not prove safe to
compile. Ipe can parse and type-check this, but the Rust backend can store a
function in a record field only under a containment proof, described below.

A function value compiles to a boxed closure. A record-of-functions is
supported when the compiler can prove it stays local: its function fields then
ride a reference-counted `Arc<dyn Fn>` carrier and the struct gets a
hand-written `Clone`, so the record builds and can be reused. When that proof
fails, the struct would derive `Clone`/`Debug`/`PartialEq` over a plain boxed
function — none of which a boxed function satisfies — so the compiler stops
here rather than hand you Rust that does not build.

`[feature: first-class-functions]`

## When it is accepted

A record-of-functions whose value never escapes its defining function (it is
not returned, stored in a larger structure, or passed onward across a function
boundary), never flows into a polymorphic position, and whose every non-function
field is itself `Clone`. Such a record is promoted automatically — no source
change needed:

```ipe ipe:skip
apply : { onClick : Int -> Int, label : String } -> String
apply c =
    c.label ++ ": " ++ String.fromInt (c.onClick 41)

main =
    println (apply { onClick = \n -> n + 1, label = "inc" })
```

## When it stays fail-closed

The record ESCAPES its defining function — e.g. it is returned, so it flows to
a caller scope the compiler cannot analyse:

```ipe
mk : Int -> { step : Int -> Int, n : Int }
mk x =
    { step = \y -> y + x, n = x }
```

A function value reaches a record field *indirectly* through a type variable —
the field instantiates to a function only at the use site:

```ipe
wrap : a -> { value : a }
wrap x =
    { value = x }

boxed : { value : Int -> Int }
boxed =
    wrap (\n -> n + 1)
```

A record mixes a function field with a non-`Clone` field (a
`Task`/`Cmd`/`Sub`/`Decoder`/opaque handle): the whole record cannot be made
`Clone`, so it cannot be a stored, reusable value.

An applicative record-codec builder — an `object ctor |> field … |> field …`
chain that threads a curried constructor through a decoder accumulator by a type
variable — is the same indirect shape. Applying the constructor one argument at a
time across a generic accumulator needs a curried-constructor lowering the
backend does not yet emit, so it stays fail-closed. Write the record codec in the
sanctioned direct form instead — a monomorphic `Decode.succeed <constructor>`
threaded through the `Ipe.Json.Decode.Pipeline` chain, which builds and reuses:

```ipe ipe:skip
userDecoder : Decoder User
userDecoder =
    Decode.succeed mkUser
        |> Pipeline.required "id" Decode.string
        |> Pipeline.required "age" Decode.int
```

## Function carriers that cannot meet

`[feature: fn-carrier-conflict]`

A function value rides one of two carriers: a plain boxed closure, or the
reference-counted `Arc<dyn Fn>` a stored function uses. Where two values meet
— the branches of an `if` or `case`, a def's return — the compiler converts a
function to the carrier the position expects. It cannot convert a function
held inside a `Maybe`/`Result` payload, nor one that reaches a generic type
parameter, without rebuilding the value around it, so such a meeting is
refused:

```ipe ipe:skip
fallback : Maybe (Int -> Bool)
fallback =
    Just (\n -> n > 0)

pick : { checks : List (Int -> Bool) } -> Bool -> Maybe (Int -> Bool)
pick cfg useStored =
    if useStored then List.head cfg.checks else fallback
```

Unwrap the payload and convert the function itself, for example by matching on
the `Maybe` and returning one function, or build both branches from functions
of one origin.

## How to fix a fail-closed case

Bind the function to a `let` (or pass it as an argument) instead, and keep plain
values in the record:

```ipe ipe:skip
apply : (Int -> Int) -> Int -> Int
apply f x =
    f x

result : Int
result =
    let step = increment in
    apply step 10
```

If storing functions in records matters for your work and your case is not yet
accepted, please nudge us at
https://github.com/ipe-lang/compiler/issues.
