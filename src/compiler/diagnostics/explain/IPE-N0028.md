# IPE-N0028: unknown kernel alias

A standard-library module binding of the shape `f = Kernel.kernel "Name"` is a
Stage-4 *kernel alias*: it routes every call of `f` directly to the built-in
kernel named by the string. The string is split at the first `_` into a
`(module, function)` pair — `"PubSub_publish"` becomes the kernel
`PubSub.publish`.

This error means the `(module, function)` pair the string names is not a
registered kernel. The compiler refuses to accept the alias, because emitting a
call to a kernel that does not exist would type-check here but then fail to
build in the generated Rust — the exact "accepted by the compiler, rejected by
the backend" hole THE SEAL forbids. Failing at compile time is the only safe
outcome.

Here a binding names a kernel that does not exist:

```ipe ipe:skip a scratch project's module is always User-origin, so Kernel.kernel here is always refused with IPE-N0042 first, never reaching the registry lookup this page documents
frobnicate : String -> String
frobnicate =
    Kernel.kernel "Widget_frobnicate"
```

A string with no `_` separator is equally malformed — it names no
`(module, function)` pair:

```ipe ipe:skip a scratch project's module is always User-origin, so Kernel.kernel here is always refused with IPE-N0042 first, never reaching the registry lookup this page documents
bogus : String -> String
bogus =
    Kernel.kernel "NoUnderscoreHere"
```

An alias whose string names a real registered kernel is accepted, and its call
sites lower straight to that kernel:

```ipe ipe:skip a scratch project's module is always User-origin, so Kernel.kernel here is always refused with IPE-N0042 first — the alias shape it accepts only in EmbeddedStdlib/FfiInterface modules
shout : String -> String
shout =
    Kernel.kernel "String_toUpper"
```

If you are porting a standard-library module whose runtime kernel is not yet
implemented on this backend, the module is *kernel-blocked*: the kernel must be
added to the registry before the alias can resolve. This is a completeness gap
to close, never a state to paper over — the alias stays rejected until the
kernel it names actually exists.
