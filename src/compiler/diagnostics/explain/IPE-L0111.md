# IPE-L0111: updating a generic record is not supported yet

You wrote a functional record update — `{ r | field = value }` — on a
record whose type is *generic*: at least one of its fields is typed by a
type variable that the enclosing function quantifies. Reading a field of a
generic record and constructing one both work; copying one with an update
does not yet.

The reason is the shape of the Rust the backend emits for an update. An
update copies the base record and then overwrites the listed fields, so it
lowers to a `.clone()` of the base. Cloning a value whose type is a type
parameter `T` requires `T: Clone`. Adding that bound is *bounded
generics* — emitting `where T: Clone` (and, in general, other trait
bounds) onto the function's type parameters — which is not supported yet.
Rather than emit Rust that fails to compile with a missing-bound
error, the compiler stops here with a clear message.

This limit is specific to the **generic** case. A record update whose
fields are all concrete types compiles fine, because the cloned type is
known and already `Clone`:

```ipe ipe:skip the concrete-record update that compiles; shown without running the checker
mkPoint : Int -> Int -> { x : Int, y : Int }
mkPoint a b = { x = a, y = b }

moveX : { x : Int, y : Int } -> { x : Int, y : Int }
moveX p = { p | x = 99 }          -- concrete record update: OK

main = println (String.fromInt (moveX (mkPoint 1 2)).x)
```

The pattern that trips IPE-L0111 is a function generic in a record field
that updates that record:

```ipe
setValue : { value : a } -> a -> { value : a }
setValue r x = { r | value = x }   -- generic record update: not yet

main = setValue { value = 1 } 99
```

Until bounded generics land, replace the generic update with a fresh
construction that names every field — that needs no clone of the base, so
no `Clone` bound is required:

```ipe ipe:skip the construct-not-update fix; shown without running the checker
setValue : a -> { value : a }
setValue x = { value = x }         -- construct, don't update

main = println (String.fromInt (setValue 99).value)
```

`[feature: bounded-record-update]`

This is a current limitation of the Ipe Rust compiler, not a problem with
your code. If updating generic records matters to your project, please
tell us at https://github.com/ipe-lang/compiler/issues.
