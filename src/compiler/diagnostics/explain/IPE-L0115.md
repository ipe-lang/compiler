# IPE-L0115: tuple pattern not supported here yet

A tuple pattern was used in a position the compiler cannot lower yet.

The supported tuple-pattern shapes today are:

* a single-arm `case` that destructures a tuple (irrefutable — variable /
  wildcard / nested-tuple elements),
* a function parameter that is a tuple,
* a **multi-arm** `case` whose scrutinee is a **tuple literal**
  (`case ( xs, ys ) of …`) — this lowers to a native Rust tuple `match`, so
  each column may be refutable (a constructor, a literal, a `x :: xs` cons),
  and
* a **multi-arm** `case` on a tuple **value** (a variable / function result,
  `case pair of …`) whose columns need no per-column coercion — every column
  is a variable / wildcard / literal / constructor / nested tuple. This
  lowers to a by-value whole `match pair { (…) => … }`.

What still reaches this gap:

* a multi-arm `case` on a tuple **value** whose column needs a per-column
  coercion — a column matched against a **string literal**, or sliced by a
  **cons / list** sub-pattern (`x :: xs`, `[a, b]`). That coercion
  (`&str` / `&[T]`) is only available on the tuple-**literal** scrutinee
  path, so write the scrutinee as an explicit tuple literal for those,
* a multi-arm `case` on a **record**, and
* a whole-value variable binder over a coerced (tuple-literal) tuple.

For the remaining multi-arm gaps, bind the scrutinee's parts irrefutably
first, then branch — or write the scrutinee as an explicit tuple literal.

## Tuple function parameter — works

Destructure the argument in the parameter list:

```ipe
fst : (a, b) -> a
fst (a, b) = a

snd : (a, b) -> b
snd (a, b) = b
```

## Single-arm tuple `case` — works

One arm, variable / wildcard elements:

```ipe
sum2 : Int
sum2 =
    case (1, 2) of
        (a, b) -> a + b
```

## Multi-arm `case` on a tuple LITERAL — works

A refutable multi-arm tuple `case` lowers when the scrutinee is written as a
tuple literal:

```ipe
zipSum : List Int -> List Int -> List Int
zipSum xs ys =
    case ( xs, ys ) of
        ( a :: xrest, b :: yrest ) -> a + b :: zipSum xrest yrest
        _                          -> []
```

## Multi-arm `case` on a tuple VALUE — works

Matching a tuple *value* (a variable, a function result) with several arms
works when no column needs a per-column coercion:

```ipe
classify : (Int, Int) -> Int
classify pair =
    case pair of
        (0, b) -> b          -- variable scrutinee + extra arm: works
        (a, b) -> a + b
```

A refutable constructor column works too — this is the `Ipe.Test` shape:

```ipe ipe:skip a fragment; Outcome is assumed from context
countFailure : (Int, Outcome) -> Int
countFailure pair =
    case pair of
        (_, Passed)    -> 0
        (name, Failed _) -> name
```

## Multi-arm `case` on a tuple VALUE with a coerced column — not yet

A tuple *value* column that needs a `&str` / `&[T]` coercion — matched
against a string literal, or sliced by a cons / list sub-pattern — still
reaches this gap:

```ipe
firstNonEmpty : (List Int, String) -> Int
firstNonEmpty pair =
    case pair of
        (x :: _, _) -> x     -- cons column on a VALUE scrutinee: not yet
        (_, "n/a")  -> -1    -- string-literal column on a VALUE scrutinee: not yet
        _           -> 0
```

Re-form the scrutinee as an explicit tuple literal so the coerced-column
multi-arm tuple `match` path applies:

```ipe
firstNonEmpty : (List Int, String) -> Int
firstNonEmpty (xs, tag) =
    case ( xs, tag ) of
        (x :: _, _) -> x
        (_, "n/a")  -> -1
        _           -> 0
```

`[feature: tuple-pattern-match]`

This is a current limitation of the Ipe Rust compiler, not a problem with
your code. If richer tuple matching matters to your project, please tell us
at https://github.com/ipe-lang/compiler/issues.
