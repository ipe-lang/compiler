# IPE-T0020: this is `Html` where an `Element` is required

An **`Element`** is a graphical building block the layout engine knows how to
place, style, and arrange (rows, columns, buttons, text). **`Html`** is finished
markup — the result of rendering an `Element`. This error means a value is
`Html` at a spot that wants an `Element`.

The usual source is a managed-update-loop shape — `Web.tea` and `WebView.app` —
which asks your `view` for an `Element` and wraps it in the page layout for you
(the equivalent of one outer `Ui.layout`). `Ui.layout` and `Ui.layoutWith` do
that wrapping themselves: they take an `Element` and hand back `Html`. So a
`view` whose body ends in `Ui.layout` returns `Html`, and the shape would wrap
already-wrapped `Html` a second time — the mismatch reported here.

A wildcard `any` return annotation hides the problem — `view : Model -> any`
lets the body settle to whatever it produces, so the `Html` slips past the
signature. Whether the annotation says `any`, `Element Msg`, or nothing, the
shape's contract is the same: hand back an `Element`.

## Wrong

The body returns `Html` because it calls `Ui.layout` itself:

```ipe
import Ipe.Ui as Ui

type alias Model =
    {}

type Msg
    = NoOp

view : Model -> any
view model =
    Ui.layout []
        (Ui.column [] [ Ui.text "hello" ])
```

## Right

Return the inner `Element` and let the shape apply the layout:

```ipe
import Ipe.Ui as Ui

type alias Model =
    {}

type Msg
    = NoOp

view : Model -> Element Msg
view model =
    Ui.column [] [ Ui.text "hello" ]
```

If you genuinely have raw `Html` to place — an escape hatch you built with the
`Ui.node` / `Ui.div` family — wrap it back into an `Element` with `Ui.html` so
the `view` result is once again an `Element`:

```ipe
import Ipe.Ui as Ui

type alias Model =
    {}

type Msg
    = NoOp

someRawHtml : Model -> Html Msg
someRawHtml model =
    Ui.layout [] (Ui.text "raw")

view : Model -> Element Msg
view model =
    Ui.html (someRawHtml model)
```

## Why the restriction exists

The shape's runtime entry point applies exactly one `Ui.layout` around your
`Element`. If `view` already returned `Html`, the generated Rust would call
`ui_layout` on a value that is not an `Element`, and the emitted crate would
fail to compile (the "type-checks in Ipê, fails in `cargo`" class this compiler
treats as a hard bug). Rejecting the `Html`-returning `view` here — at
type-check time — keeps every accepted program buildable.

## Glossary

* **`Element`** — a graphical node in the `Ipe.Ui` layout tree (rows, columns,
  buttons, text). The managed shape lays these out for you.
* **`Html`** — finished markup, the result of rendering an `Element` through
  `Ui.layout` / `Ui.layoutWith`. Reach for `Ui.html` to fold raw `Html` back
  into an `Element`.
* **managed update loop** — the `init` / `update` / `view` / `subscriptions`
  architecture (TEA) that `Web.tea` and `WebView.app` run for you.
